## 修改内容：最小适配清单

本次只新增本文。以下列出后续实施所需的最小改动，不表示已经实现。

### 1. 参数化场景读取和坐标，不重做任务格式

| 当前硬编码 | 新版所需处理 |
|---|---|
| `load_scene` 要求 `len(docks)==24` | 支持明确声明的 100 个充电位，同时保留旧版入口/身份，避免改坏已冻结结果 |
| 每列坐标 `rack.x + (bay+.5)*.6` | 读取 `spec.slotPitch=1.2` 或验证后的 task-locations 字典 |
| `Navigator.nx=301, ny=241` | 由 width=90、depth=76、gridStep=.2 推出边界，不能继续裁成60×48 |
| 货架层数/列数推导 | 读取并校验 3层×2面×8列=48/架、36架总1728；保留原ID语义 |

具体坐标反例：新 `R01-L1-C1-F1` 应为 `(18.9,13.3)`，`R01-L1-C8-F1` 应为 `(27.3,13.3)`；继续旧公式会错误地产生 x=18.6 和22.8。即使任务 ID 一样，旧坐标也不能继续使用。

另外，旧 `Roadmap` 对 `kind=='home'` 使用 `approachY`，其他类型则读 `gate`；新 `home-alias` 没有 `gate`。必须先解析别名与规范泊位，再构造进出连接，不能只放宽24桩断言。

### 2. 一个规范物理泊位，两个兼容位置名称

以 `C-A01` 为规范物理资源，`P001` 只是初始归属/兼容名称：

```text
P001 --alias_of--> C-A01
physical capacity(C-A01) = 1
```

- 规范泊位数量是100，不是把 homes 与 docks 相加得到200。
- 对同址 P/C 进入、占用、离开和充电使用同一个容量/预约状态。
- 机器人初始停在其对应充电兼待命泊位，但 `home alias` 不应在状态变化后被误当作额外空闲停车位。
- 若最小实现采用“一车一个初始归属泊位”，也必须明确是否允许使用其他充电位，不能一边默认固定返 home、一边允许该 home 对应充电位被另一车长期占据。
- 候选 `noPerTaskDockReturn=true` 的含义是正常有任务时不强制每单都回桩。保留安全退路可以作为未匹配时回退，但不能把“安全尾段”误解成每单必须实际执行返桩。

### 3. 空桩可过，但所有实体机器人持续占用

这是最重要的语义迁移，不能仅删静态框：

- 旧 `Navigator.private` 把每个 home 和 dock 都当作静态禁入矩形。新图同址 P/C 会重复成框：允许 P001 仍被 C-A01 挡住，反之亦然。
- 新图 `staticCollision=false` 表示忽略空充电硬件，不表示忽略停靠机器人。
- 旧版待机车主要依靠私有泊位静态排除保证安全。若清掉私有框，必须同步显式保留所有 idle、充电中、充满待命、故障隔离机器人的真实圆形占用；运动轨迹结束后也不能让该车从预约中消失。
- 通行可以经过当前空位，但必须与已预约的停靠/离开轨迹相容；同一物理泊位不能因 P/C 名称不同被双重分配。

这里需要的是清楚的占用模型和基本安全验证，不要求继续实现更复杂的交通优化算法。

### 4. 充电配置、状态记录和图谱同步支持100位

当前 `Config.chargers` 上限24，初始化和图谱历史都用 `docks[:12]`、`docks[12:]` 配对；仅将配置改成100仍会遗漏/错误选择泊位。

最小要求：

- 从实际规范 dock 列表选择配置内的泊位，不假定12+12。
- `available_at`、occupant、reserved 状态统一使用规范物理泊位，反映“充满仍停着”，不能 SOC 到目标就立刻当作空间空闲。
- 图谱可保留 P/C 两个位置名称和别名关系，但统计实际充电/停车容量时只计一次；同一机器人的驻留、离开、回桩应可沿时序查询。
- 100个桩是空间/停车容量，不自动证明电力系统能支持100台全速同时充电。继续采用明确的净 SOC 模型即可，但需固定是否限制同时充电数、保留假设声明；本阶段不额外研究供电系统。

### 5. 数据和图谱不换主接口，只更新场景身份

- 保留七字段任务 CSV、货物 ID、货位 ID、IN/OUT ID，初始库存和容量语义可以继续对齐。
- IN-1…IN-8 现在位于西侧 x=7.6；OUT-1…OUT-8 位于东侧 x=82.4。ID相同不等于旧坐标或旧动线仍有效。
- 同学按新位置字典生成/核对任务；热点应按物理区域重新选，不能复用旧编号范围代表旧区域。
- 新地图、新 manifest/哈希、新验证目录保留；不得直接覆盖旧manifest地图哈希而称原数据已通过新场景。
- 旧数据的货物依赖可以复用，但距离推导的 due_time 需重算或标明只是兼容输入后独立验证，不能倒填算法实际完成时间。
- 知识系统沿用任务、AgentState、货物持有者、位置、Step/Event 及协作关系；只将新坐标、规范泊位和别名关系写入新 run。旧 run 的空间知识不能被新图覆盖。

### 6. 验证收敛到知识主线

只做适配必要的门禁和一个代表性的普通运行，不再扩展窄道极限矩阵：

1. 确认地图读取尺寸、1728货位坐标、100 P/C同址别名及初始100实体位置正确。
2. 确认空位可以通行、有人占位不能穿越，停靠/充满待命占用不会丢失；没有双重泊位计数。
3. 用已有普通到货思路生成/迁移小规模独立输入，核对真实取放、容量、充电、事件与货物守恒。
4. 以知识系统为验收重点：谁知道什么、何时知道、何时发生位置/电量/任务变化，历史与当前状态是否一致、机器人能否共享查询到需要的信息。
5. 确认事件进入 Journal/Neo4j、时序查询与恢复有效后，再按主线需要扩大图规模和查询性能验证。100活跃、百万级/延迟仍保持独立真值，不从静态地图尺寸推出通过。
