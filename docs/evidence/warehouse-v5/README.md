## 文件怎样对应

- `case-summary.json`：五场景任务、迟到、流转时间、电量、间距与输入身份。
- `frozen-release-identity.json`：选定调度参数及源码身份。
- `release-files-sha256.json`：150个原始交付文件的逐文件SHA。
- `full-regression-summary.json`：冻结版本268项Python回归的汇总（263通过，5项数据库集成使用单独开关）。
- `warehouse-phase1-gate.json`：仓库阶段整体检查结果。
- `quiescence-independent-RAM-check.json`：业务结束后的返泊核对。
- `hundred-active-replay/`：模拟804秒时100台业务活动的独立重放状态及连续距离核对。
- `publication-provenance.json`：这些文件的来源与原始摘要。
- `git-publication-regression.json`：独立交付检出再次运行268项测试的结果。
- `git-publication-smoke.json`：使用`python -S`完成19条任务和真实HTTP回放的核对，包含100机器人帧、最终地图及源码身份。

## 100台同时作业怎样核对

804秒状态中，52台携货去目标、35台去取货、5台放货、8台取货，合计100台。重放与0—800秒的81个原有10秒记录点逐字段对齐，804秒这一瞬间另作逐秒核对。该运动段4950对机器人的最小连续中心间距为1.13137085米，设计要求为1.1米。

原始10秒采样帧的业务峰值为98台；逐秒重放提供采样间隙中的100台状态，两份材料各自保留身份。

## 复现与文件身份

五份合成原始输入与运行配置位于`data/examples/regression/`。完整命令见[仓库设计指南](../../WAREHOUSE_DESIGN_GUIDE.md#10-从零运行一个小示例)。检查点和完整轨迹由运行时写入新的`data/local-runs/`目录。

冻结150文件中的运行源码、地图、配置、前端及测试逐字节保留；本次新增README、指南、样例组织与Git规则。仓库以全部backend源码计算执行身份，方便恢复时核对版本。布局和CSV使用内容摘要，因此本分支通过`.gitattributes`保留这些文件的原始换行。

部分原始证据保留生成时的环境目录，便于原实验追溯；新运行请使用指南给出的仓库相对路径。
