### 业务相关性怎样定义

独立结构标签为：载货状态相同、阶段族相同、SOC差≤10个百分点、位置距离≤15m。它与余弦分数分别定义，不预测任务成功。

- 9个查询有至少5个相关候选；最早查询有4个；两个低电查询在允许的历史域内没有相关候选。
- 因此12case可达到的业务Precision@5上界为49/60=0.8167，17D本轮达到该上界。所有早期/无相关历史case仍保留在分母中。
- 这证明新表示在这个小型、声明清楚的结构用途上比含身份/时间盐的原表示合适，不能外推为文本语义、普遍场景质量或调度收益。
- 无相关历史时，最高近邻分数也不能被解释为成功经验。现有来源只有少量受控低电事件；后续可在独立扰动配置中增加可重复协作场景，无需给任务CSV增加电量或向量列。

### ANN质量口径

这里按新历史检索用途排除了自身机器人和20提交近邻，故与此前完整查询中的自检/全字段压力口径不同。全局ANN召回后再过滤run和历史截止，在早期水位会不足K；增加候选100→1000改善召回，但不构成精确全集保证。现有完整API继续保留不足K后的精确回退。不得用原先少量自命中检查替代本轮更严格候选域的质量评价。

## 3. 新业务API真实图验证和热点

`BusinessRetriever.search`默认只读窗口`[seq−60, seq−20]`，排除查询机器人；完整100状态/提交的来源中为4059候选。最多读取预算+1条，超额明确拒绝，不截断后冒充精确。

来源核对覆盖seq/robot：350/9、576/88、6000/66、10000/100。4次均与Oracle完整候选域的精确顺序、标量分数、返回物理字段和原payload SHA相同。

|诊断版本|4次完整服务耗时ms|
|---|---|
|原始标量范数重复检查|1014.106 / 277.540 / 426.529 / 347.868|
|验证/归一化后直接精确点积|296.004 / 156.027 / 147.735 / 181.765|

首次冷编译与缓存状态不同，不能把1014→296全部归因于算法。优化只利用新构造向量已归一化的事实，避免每候选重新计算范数、遍历数值类型；不缓存动态事实或整份结果。

优化后阶段：header/源查询约2.9—6.5ms，4059候选图读取约110—214ms，校验和精确排序约34—76ms。主要热点是跨Bolt返回大量候选。下一步更高收益的方向是把有界域中的精确排序下推到数据库，只返回TopK，同时保留预算超额检测；本轮未改该冻结接口，避免无证据扩大改动。
