# 独立压测控制台

页面负责配置实验、调用原压测工具、展示结果。仓库仿真仍在原页面运行，两者互不替换。

## 1. 打开页面

已有本项目副本、Python 3.10以上即可启动，不要求压测客户端安装Neo4j驱动、GPU库或Node.js：

```bash
python pressure_test.py --gui
```

服务器上也可执行 `bash pressure_test.sh --gui`。打开 `http://127.0.0.1:14595/`；终端保持运行，Ctrl+C退出控制台并停止其自有测试，不停止原仓库。

Pro6000提供的本轮待检查实例已单独启动，映射到本机同端口14595。自己启动其他实例时可用：

```powershell
ssh -N -p 28941 -L 14595:127.0.0.1:14595 wz@58.48.54.157
```

界面只监听服务器127.0.0.1，通过SSH访问，不公开到互联网。若端口已占用，可将GUI的`--port`与映射两端同时改为另一个端口，例如14596；两端同端口便于保持Host校验一致。不要关闭别人的服务。

**请求由GUI后端所在设备发出。** GUI在Pro6000启动，压力来自Pro6000；GUI在Windows启动，压力来自Windows，并包含到目标服务的网络/隧道耗时。页面右上角显示实际发起设备。

## 2. 第一次操作

1. 地址填真实查询服务，例如Pro6000内的 `http://127.0.0.1:14192`，点击“检查连接”。14595是控制台自身端口，不是查询目标。
2. 保留“小检查”预设，点击“开始实验”：1客户端3请求，另有1条连通性检查。
3. 等待状态变为“本轮样本通过”或明确的失败状态。右侧显示指标、图表、分类统计和请求明细。
4. 再选择其他预设或调参数。超过小检查的负载需要勾选确认。后端再次验证参数，不只依赖浏览器输入框。

同一个控制台一次只运行一个实验。测量期间显示阶段、已运行时间与日志；未封口的gzip不提前解压作为正式数据，图表在请求排空后更新。页面不会捏造实时完成百分比，也不会把部分结果标成全部通过。

## 3. 可以调哪些参数

|参数|用途|
|---|---|
|预设|快速填好小检查、100客户端日常错峰、轻突发或重突发|
|查询内容|自身、就绪、全局、区域、补能、帮手、历史、进度，或自身＋全局混合|
|客户端数|模拟有多少个独立请求者，范围1—100|
|进程数|实际开多少个OS客户端进程，不能超过客户端数；100客户端/1进程和100进程要分开解释|
|持续时间|请求发起上限1—300秒，不包括启动客户端、排空超时、离线分析时间|
|每客户端请求上限|数量与时间先达到者停止；错峰/固定到达率可填0；闭环必须设置正上限|
|负载模式|闭环收到响应再发；错峰按客户端间隔；固定到达率按全局计划频率|
|间隔/到达率|错峰的每客户端间隔、固定到达率的全局次/秒，未选该模式时不生效|
|超时|单次HTTP等待上限，1—60秒|
|历史窗口/预算|提交批次窗口，以及完整事件/历史状态预算；超出预算保留错误，不自动裁剪|
|混合比例|自身和全局查询的抽样权重；不是强制配额，实际次数在分类表中查看|

单轮计划到达预算限制100000；关闭无界高速闭环，防止误填参数导致超出预期负载。研究确实需要更大规模时，使用原高级工具并明确资源与实验身份。

开始时自动读取当前run和已提交seq，之后整轮固定这个知识点，避免一轮混入不同历史切面。不会每条自动取最新，也不会冻结或暂停原仿真；期间若原页面切换run导致查询失败，失败仍保存。

## 4. 怎么看图表和结果

- **指标卡**：平均、P99、最大、超过500ms、成功/总到达、错误/丢到达。时间包括完整HTTP和JSON解析。
- **延迟分布**：全部已保存的有计时请求，包含有耗时的失败；超过500ms区间用红色柱表示。无耗时的丢到达不塞入0ms桶。
- **每秒完成请求**：从原请求完成时间分桶，不把配置到达率当实测吞吐。
- **延迟随时间变化**：每秒平均与最大耗时；500ms高于当前量程时明确标注，不把图裁剪成看似达标。
- **请求结果组成**：成功、HTTP错误、网络错误、解析错误、丢到达等原分母。
- **查询分类**：各类查询的平均、P99、最大等独立统计。混合负载不平均两个P99充当总P99。
- **请求明细**：按慢请求倒序分页，支持只看失败/丢到达，展示HTTP状态和队列/服务耗时；缺失值显示空缺，不猜测。
- **历史对比**：最多勾选3次已完成实验，按查询类型对比。参数、run、seq或机器负载不同会影响比较，不能自动推导算法因果收益。

可以下载中文Markdown报告、摘要JSON、原始统计JSON、请求CSV及实验配置。CSV是原记录的轻量索引；完整请求/响应仍在服务器实验目录的 `output/client/*.jsonl.gz`，不因图表分页而被删除。

## 5. 停止、历史与结果位置

“停止本次实验”只向该控制台创建的测试进程发送中断，等待原发起器清理客户端。停止不会重试剩余请求，状态保留为“已中断”。

默认记录在项目 `data/pressure-gui/job-编号/`。GUI重启后读取历史；上次仍写着运行中的记录标为“未确认完成”，不凭旧PID重连或杀掉其他进程，也不改成成功。原始文件一直保留。

可用 `--data-root`指定个人新记录目录。实验的 `job.json`与参数保存在外层，CLI原件在 `output/`。代码和数据不自动Git提交或推送。

## 6. 样本通过与正式验收的区别

这个GUI复用原 `load_harness`、`load_validation`和报告计算，失败不自动重试、不隐藏、不删样本；连通性预检单列，每种查询各1次，不混入正式负载统计。

当前直接测公开catalog接口，提供时延及返回结构检查。它没有自动做百万前缀规模、独立journal/oracle来源验真、100机器人实际工作、持续写入或历史控制验收；页面把这些资格明确列为未取得。服务端实际并发也不能拿客户端数代替。

Agent私有读写、ANN和完整百万A/B仍按[高级手册](LOAD_TEST_COOKBOOK.md)单独测。合并新API时维护 `config/pressure-test.json` 与相应结构适配；改POST路径仍受原发起器只读白名单限制。

## 7. 实现位置

`ops/pressure_plan.py`校验受限参数，`ops/quick_load.py`调用原测量工具，`ops/pressure_gui.py`管理自有子进程和历史、只读生成图表，`dist/pressure-lab/`是纯原生HTML/CSS/JavaScript页面。无外部CDN或前端构建依赖。

控制操作有Host/Origin与随机控制令牌检查；浏览器不能传任意命令、任意路径或跳过高负载确认。客户端子进程移除不需要的NEO4J环境变量，避免把数据库凭证带到只读压测进程。
