# 120秒采样完整周成对回归

### 任务背景

300秒周期采样的完整七天运行最终得到994,184个同run去重节点，保留为完整基线。为使增长中的同run在后续查询窗口达到百万节点，单独建立120秒周期采样实验，继续使用原始七天任务和物理策略。

### 关键结论

- 新实验根目录为`/data/workspace/wz/warehouse-platform-density120-20261028`，保留全部旧目录和结果。
- 243份冻结源文件与旧`source-v2`逐SHA相同。任务、初始库存、manifest及14个低电扰动保持原字节。
- 新实验唯一采样参数变化为`commit_seconds=120`；物理调度、默认配置和业务输入保持一致，使用新run编号和全新output。
- required模式继续先运行至86,400秒暂停，再按原身份恢复至604,800秒；rules模式独立完成原始整周输入。
- 每阶段内部墙钟预算26,000秒，外层28,000秒。失败会保留日志并停止，不自动重试仿真。
- 两组生产者已实际推进，检查点均记录120秒周期，物理配置SHA一致；私有连接环境文件权限为0600。
- 当前记录说明实验部署，最终通过结论以新目录的完整结果、源控制审计、物理对照及逐查询前缀规模审计为准。

### 执行过的操作

1. 在全新目录复制冻结源和输入，写入`density-bootstrap.json`保存复制身份与外部工具SHA。
2. 并行启动required与rules监督脚本，分别保存PID、日志、阶段退出码及日志SHA。
