# 知识图谱工作台上下文追溯前端

## 任务背景

继续参考 LaDe 的动态图谱工作流，增强仓储知识图谱工作台的前端可读性。目标是让任务、机器人和全局协同记录从原始文本/JSON式展示，变为可理解的时间线与上下文分组；不修改实时仿真和图谱写入链路。

## 关键结论

- 任务追溯现在以 tick 顺序展示分配、取货、执行状态、货物交接、完成和运行事件，交接与普通事件有不同视觉语义。
- 机器人追溯现在分为“当前自身状态、短期图谱记忆、任务与协作”，对应 LaDe 的自我状态、近期轨迹/事件、任务上下文查询模式。
- 全局记录现在分为“运行摘要、派单快照、协同与交接”，并将 Assist、Handoff、RunStat 和全局事件合并为按 tick 排序的时间线。
- 所有新展示只调用已有的带 `run_id`、tick 和 limit 限制的只读接口；不默认查询全图、不增加高频轮询。
- 采样状态与完整 Step 仍明确分开：机器人卡片会保留请求 tick、实际采样 tick 与状态滞后信息。

## 执行过的操作

- 阅读 `backend/warehouse_graph_query.py`，确认任务追溯含 `ExecutionState`、`RuntimeEvent`、`Handoff`，机器人追溯含最新状态、轨迹、执行与事件，全局接口提供 `RunStat`、`DispatchState`、`Assist` 和 `Handoff`。
- 修改 `dist/kg.html` 和 `dist/styles.css`，完成前端信息结构与样式。
- 未启动 Neo4j、Ray、全局 writer、4173 服务或测试命令；只执行了静态差异检查。

## 修改内容

- `dist/kg.html`
  - 在全局记录区新增上下文分组容器，读取交接记录并与协助、事件、统计记录按 tick 合并。
  - 在机器人追溯区新增上下文分组容器，展示当前状态、短期记忆和任务/协作摘要。
  - 任务时间线接入 `ExecutionState`，并将生命周期、交接及事件按 tick 排序。
  - 新增前端辅助函数，用 DOM API 生成内容，不拼接不可信 HTML。
- `dist/styles.css`
  - 将任务/机器人/全局事件改为 LaDe 风格的纵向时间线。
  - 为分配、取货、完成、交接、协助、状态采样、全局统计配置不同视觉标签。
  - 新增响应式上下文卡片栅格。
