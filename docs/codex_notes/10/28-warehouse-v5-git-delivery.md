# 仓库V5分支交付整理

### 任务背景

数据生成与仓库仿真由两位同学分别负责。本次把已验收的仓库布局、调度与仿真整理为独立Git分支，并提供面向首次接触项目的计算机专业学生的说明和可运行输入。

### 关键结论

- 仓库采用90×76米、1728货位、100机器人及100充电兼待命泊位的选定布局。
- 五类固定场景均完成全部任务，迟到与安全失败记录为0；高峰有100台同时业务作业的独立核对。
- 150个冻结源码、配置、地图、前端与测试文件逐字节保留，Git规则保护源码和数据的内容身份。
- 分支附带19条任务样例、五组原始合成回归输入、数据契约及位置表。
- 仓库指南从业务流程、容量和电量规则讲到调度、避碰、源码对接与运行命令。
- 查询访问层优化使用独立版本与对照记录，仓库布局和调度继续作为稳定实验载体。

### 执行过的操作

1. 核对fork的main基线，建立`wz/warehouse-design`交付分支与独立检出目录。
2. 由冻结150文件清单构建明确发布白名单，核对文件SHA和换行。
3. 整理原始样例、五场景输入、地图和数据合同，生成本目录对接包的文件校验清单。
4. 补充根README、仓库设计指南、兼容入口说明与精简验收材料。
5. 在交付检出目录再次完成268项自动测试：263通过、5项数据库集成按开关跳过，耗时223.198秒。
6. 使用`python -S`运行19条任务，全部完成、迟到和安全失败为0；临时端口提供的地图、100机器人帧及回放页面全部返回成功，随后关闭临时服务。具体提交记录可从本分支Git历史追溯。

### 修改内容

源码按V5冻结交付组织，文档和样例通过清晰目录对接；`.gitignore`隔离运行产物，`.gitattributes`保留已验证文件的原始字节。原交互服务入口保持可用，V5提供独立的中央仿真与回放入口。

### 后续建议

数据生成同学先依据位置表提交一份可校验的一日输入，双方固定分支、地图SHA和配置再运行。新的任务分布、算法或知识查询接入各自使用独立运行目录与对照结果。
