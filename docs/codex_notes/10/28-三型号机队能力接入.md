# 三型号机队能力接入

### 任务背景

复用原仓库的A1、R2、X3型号，将取放能力真正接入新版V5仿真。现有线上服务、冻结源码和历史回归保持不动，新混合机队作为显式配置进行独立测试。

### 关键结论

- 默认 `fleet_mode="all-x3"` 保持100台X3；`fleet_mode="mixed"` 默认采用原编号规则的40台A1、40台R2、20台X3。`fleet_counts` 可显式指定其他总数100的组合，确定性地分散到各泊位。
- A1/R2/X3分别复用原代码的1/2/3层、0.55/1.05/1.55m高度与0.18/0.52/0.92m额外伸出参数。这些是仿真参数，未标定为硬件规格。
- 入库检查目标货位，出库检查源货位；完整任务的两端都检查。已经完成取货后的接力/故障恢复仅检查余下目标，因此高层取出的出库货物可以交给A1送到地面出库点。
- V5在匹配前屏蔽不可达组合；直接派单、故障恢复规划、多机器人恢复提交，以及实际取货、交付、接力转移前均有能力门禁。
- 低层任务有可配置的软代价，合理优先使用短臂型号；该软代价不降低匹配基数，也不突破优先级或安全门禁。
- 默认三层地图的全X3模式仍保留已有派单决策；跨源码恢复坚持现有的严格身份校验。旧检查点由原冻结源码恢复，新字段和新源码不自动迁移旧检查点。

### 执行过的操作

阅读原 `backend/domain.py`，以及wide/V3/V4/V5的派单、动作、接力、故障和恢复路径。新增纯能力模块和真实执行层测试；使用本机捆绑CPython运行测试，未访问或修改服务器。Windows本机没有 `run_in_lade.sh` 所需Linux环境，因此这里没有调用该启动器。

### 修改内容

- `backend/wide/capabilities.py`：型号profile、确定性机队分配、垂直层位/高度与额外水平伸出的独立约束。
- `backend/wide/sim.py`：显式Config选项、初始化真实型号、元数据、任务规划/派单/恢复/动作/接力门禁与恢复身份检查。
- `backend/scheduling_v5/sim.py`：匹配时使用本次真实候选列，屏蔽不可达组合并施加软代价。保留原派单主体，重试删列后不会重新猜测机器人列身份。
- `tests/test_mixed_fleet.py`：配比、异常配置、能力、匹配、恢复、接力和19任务实际运行测试。

配置示例：

```json
{
  "fleet_mode": "mixed",
  "fleet_counts": {"A1": 40, "R2": 40, "X3": 20},
  "capability_spare_cost_seconds": 15.0
}
```

`capability_spare_cost_seconds` 的合法范围为0—300，只在显式mixed模式生效。低层作业使用高型号时，以多余的可达层数乘此值加入代价；可设置0作为无保留偏好的对照。

**水平与空间边界：**`extension`为额外伸出，不能理解为整条机械臂长度。双面货架已有独立的接近点；没有声明额外需求时，`required_extension_m=0`。货架可显式声明额外伸出要求，超过型号参数会拒绝。货位作业高度采用与页面一致的层距和箱体中心模型。本轮没有增加机械臂IK、手臂接触碰撞或交接姿态动力学。

### 验证范围

新增测试包含原19任务真实运行：19/19完成、0迟到，三种型号均执行过任务，全部派单能力检查通过且无不安全事件。另以实际高层入库任务注入低电：接力接收者为X3，持有待转移货物的中间检查点恢复后，两条执行链的机器人状态和货权保持一致。

故障恢复测试额外证明未取货时不能绕过高层源点约束；已取货时按余下目标检查；直接传入多机器人恢复方案也不会绕过能力检查。

本地原始测试日志位于 `data/local-check/mixed-fleet-tests.log`、`mixed-fleet-regression.log` 和 `mixed-fleet-regression-final.log`。最终回归数量以最终日志为准；该小样例不代表100台混合机队在任意高峰、任意扩仓尺寸均满足运力。

### 后续建议

- 在相同任务率、截止时间和seed下，分别比较全X3、40/40/20和必要的20/30/50对照，按型号统计吞吐、忙时、空驶和排队。
- 扩仓后重新评估各层需求与X3数量，保留失败场景；不要通过延长时限或把高层任务转给短臂机器人掩盖不足。
- 新版本部署需使用独立源码/运行目录和新的源身份，不能热替换线上冻结Runtime，也不能用新源码继续原回归。
