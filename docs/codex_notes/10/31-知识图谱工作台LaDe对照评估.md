## 任务背景

评估当前仓储知识图谱工作台是否已达到参考 LaDe 后应具备的功能完成度，并判断是否还应继续扩展页面。

## 关键结论

- LaDe 的“知识图谱”实际是内存时序事件列表，不是 Neo4j 属性图；它主要服务于任务分配上下文与最近事件展示。
- LaDe 页面提供受控查询、查询耗时、结果表格、查询历史和 JSON 导出；不开放任意图谱编辑能力。
- 当前工作台已具备真实 Neo4j 查询、完整 Step 锚点、tick 与仿真时间对应、任务/机器人追溯、运行态与全局记录、关系证据图、查询历史与导出。
- 对于本项目目标，当前 KG 页面已达到并超过 LaDe 中可合理迁移的展示和查询能力。
- 不建议继续把 4173 的运行控制、14185 的回放控制、任意 Cypher 编辑器或 LaDe 的 LLM 调度面板搬进 KG 页面；它们会造成页面职责重叠。
- 后续应优先进行真实 Run 验收、查询性能与数据完整性验证，而不是继续增加前端区块。
