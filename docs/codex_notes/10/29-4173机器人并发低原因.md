# 4173 机器人并发低原因

## 任务背景

用户观察到 4173 页面同一时刻只有一个机器人在运行，询问是否是测试数据集导致。

## 关键结论

- 是数据集的任务发布时间导致的，不是 100 机器人引擎或 Ray 的问题。
- 当前使用的是 `data/generated/warehouse100-day1`：6912 条任务分布在 24 小时（86375 秒），平均约 4.8 条/分钟，前 30 分钟每分钟只有 3–6 条。
- 当前 run `warehouse-3fafa0f3f4cb` 在 tick 167（约 42 模拟秒）时，`datasetTasksReleased=2`、`datasetTasksWaiting=0`，只释放了 2 条任务；`assignedRobots=2`、`inProgressTasks=2`，其余 98 台机器人空闲是正常的。
- `maxActiveRobots=100`、`workerProcessCount=100`，引擎没有限制并发。
- 换用高峰期数据集 `data/examples/regression/peak`（1728 条任务/3600 秒，前 10 分钟 49–82 条/分钟）可以很快看到大量机器人同时工作。
- 本次运行同时验证了上一轮修复：`Run.robot_count=100`、`/tasks` 不再重复、`runtime-trace` 的 `robot_id` 不再为 null。

## 执行过的操作

- 调用 `http://127.0.0.1:4173/api/health` 与 `/api/snapshot`，读取 `tick`、`datasetTasksReleased`、`assignedRobots`、`inProgressTasks`、`maxActiveRobots`。
- 统计 `data/generated/warehouse100-day1/tasks.csv` 的发布时间分布。
- 对比 `data/examples/regression/peak` 的任务量与前 10 分钟发布速率。
- 查询 Neo4j 新 run 的 `Run.robot_count` 与节点计数，确认修复生效。

无。本次仅诊断，未修改代码或数据。

## 后续建议

1. 想观察 100 台机器人并发，改用高峰数据集：

```bash
export WAREHOUSE_NEO4J_PACKAGE_DIR='data/examples/regression/peak'
export WAREHOUSE_SIMULATION_DATASET_DIR='data/examples/regression/peak'
```

2. 若需要静态图谱与 `T-*` 任务关联，先用同一数据包导入：

```bash
./.venv/bin/python scripts/import_warehouse_neo4j.py \
  --package-dir data/examples/regression/peak --apply
```

3. 重启 4173 时使用新的 checkpoint，避免与原 run 混用。
4. 若继续用全量日数据，可接受低并发；这是业务输入的真实节奏，不是渲染或调度缺陷。
