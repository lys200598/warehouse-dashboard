# 知识图谱工作台首期联动改造

## 任务背景

在不影响当前 4173 实时仿真、主进程派单、Ray 机器人 Actor、全局记录写入和 Neo4j 写入链路的前提下，参考 LaDe 的运行态时间锚点与追溯方式，增强仓储知识图谱工作台的可读性，并让 4173 可直接进入当前对象的图谱追溯。

## 关键结论

- KG 页面新增“图谱调度锚点”，只读取当前 Run 的最后一个完整 `Step`，展示完整 tick、已收齐的机器人回执、实际派单状态来源和图谱写入积压。
- 运行锚点使用已有 `/steps/latest?states=false` 接口，不新增写入、轮询或调度操作；查询失败也不会影响仿真。
- 4173 顶部的“知识图谱工作台”链接现在会携带当前 `run_id`、tick、选中机器人和当前任务 ID，打开 KG 页面即可自动定位。
- KG 页解析链接参数后，会预填追溯字段；携带任务或机器人参数时自动发起一次对应的有界只读追溯查询。
- 任务追溯改为以“分配、取货、完成、交接、普通事件”区分颜色的生命周期标签；交接关系不再混在普通文本中。
- 本次未改动任务派单、图谱写入频率、状态来源、数据集格式或 Neo4j 图模型。

## 执行过的操作

- 阅读 `ops/warehouse_live.py`，确认 4173 当前使用的实时服务已提供任务、机器人、运行态、全局记录与最新完整 Step 的只读接口。
- 阅读 `ops/warehouse_live_runtime.py`、`backend/global_writer.py`、`backend/robot_actor/ray_actor.py`，确认完整 Step 的回执字段为 `expected_robot_count`、`received_robot_count` 和 `complete`，以及页面可展示的 `robotGraph` 状态字段。
- 阅读并修改 `dist/index.html`、`dist/app.js`、`dist/kg.html` 与 `dist/styles.css`。
- 执行 `git diff --check`；未启动 Neo4j、Ray、全局记录服务、4173 服务或测试命令。

## 修改内容

- `dist/index.html`
  - 为知识图谱入口增加稳定 DOM ID，并更新前端资源版本参数以避免浏览器使用旧缓存。
- `dist/app.js`
  - 根据当前实时帧与选中机器人更新 KG 链接的 `run_id`、`tick`、`robot_id`、`task_id`；仅改变链接，不发送控制请求。
- `dist/kg.html`
  - 新增完整 Step 运行锚点卡。
  - 支持 URL 深链接参数自动预填并定位任务/机器人追溯。
  - 任务追溯加入 tick 过滤，修正执行记录使用 `current_robot` 字段，并突出显示交接事件。
- `dist/styles.css`
  - 增加运行锚点卡、任务生命周期事件标签及四列到两列的响应式栅格样式。

## 后续建议

1. 启动现有服务后，从 4173 选择一个正在执行任务的机器人，点击“知识图谱工作台”，确认 URL 参数和 KG 页自动追溯一致。
2. 使用一个包含完整 Step 的 Run 验证运行锚点的回执数为 `100/100`，并确认内存派单与 Neo4j 图谱读取模式被正确区分。
3. 下一期可将全局协助、负责人变更和 DispatchState 从文本记录整理为独立的异常/交接面板。
4. 之后再增加受节点数限制的任务/机器人 1--2 跳关系图，不默认渲染整张百万级图谱。
