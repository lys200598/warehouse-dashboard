# 原版规划路径恢复与仿真显示修复

## 任务背景

原始主页允许点击机器人，查看它接下来要走的规划路径。接入新版真实仿真时，这个位置被改为显示过去走过的轨迹，造成未经要求的功能漂移。本轮恢复原功能，修复斜向移动跳动、重复帧朝向归零，并检查其他原页功能。

修改落在原有 `dist/index.html` 使用的 `dist/app.js` 和数据适配层，继续使用原来的页面与交互。没有新建替代页面。独立测试地址为 **http://127.0.0.1:14197/index.html**；14193 等旧服务保留作对照。

## 关键结论

- 点击机器人后，亮黄色虚线显示后端已经预约的剩余作业路线，保留原有终点圆点、路径开关及少量其他机器人的淡色路径。路线包含当前作业已安排的后续运输和返回段，末端圆点可能位于待命位。
- 路线来自实际作业 `jobs/parts`。无有效计划的机器人只保留当前位置，界面不补画“当前位置直达货架”的猜测路线。历史位置缓存没有继续承担规划路径显示。
- 斜向移动按真实上一秒的执行折线插值；有拐点时沿各段行走。重复帧保留朝向及原插值时钟，不重播、不倒退；跨帧缺口直接采用真实位置。
- 补回任务货格高亮、任务层位、真实阶段进度及状态导出字段。出库任务显示“出库”，任务队列在取货前也能显示已绑定的货物 ID，俯视模式可以单击机器人。
- 最终前端 **103/103** 测试通过，本机相关 Python **30/30**、服务器相关 Python **46/46** 通过。独立核对真实暂停帧的 100 台位置、50 份计划/执行/任务绑定，错误数为 0。
- 最终版本另采集 60 次真实 API 帧，覆盖 201 个斜向执行片段、26 次重复帧；6,500 次插值与路径起点检查、2,600 次重复帧朝向检查通过。
- 地图、数据集、调度算法、交通预约规则、知识查询接口及原服务未改；保持 100 台机器人、临时最多激活 50 台。本轮修改尚未提交或推送。

## 修改内容

### 后端仅增加显示证据

- `ops/live_motion_view.py`：读取实际作业的路径段，输出 `motion` 与 `work`。`motion` 包含计划身份、剩余路线、上一秒带时间戳的执行折线和朝向；`work` 包含真实任务、货物、货格、源终点和进度。
- `ops/warehouse_live_runtime.py`：在发布给界面的快照副本上附加上述字段。实际机器人、任务、调度计划和图谱写入对象不添加这些界面字段。

可以把它理解为：仿真本来已经知道机器人下一秒走哪条路线，本轮把这份已确定的结果传给页面，页面不再自行推测。

### 前端保留原图层和交互

- `dist/motion-view.mjs`：校验运动字段的 run、实例、机器人、tick、端点与时间范围；按真实折线插值。
- `dist/original-platform.mjs`：把真实快照转换为原版页面模型，保留最后有效朝向，恢复任务货格关联。
- `dist/dashboard-view.mjs`：集中处理任务标题、进度、重复帧与单击选择判定。
- `dist/app.js`：恢复原规划路径绘制；使用上述字段，补回任务详情、高亮、动作进度和俯视选择。
- `dist/live-model.mjs`：补齐 CSV 字段与转义。
- `tests/test_live_motion_view.py`、`tests/motion-view.test.mjs`、`tests/dashboard-view.test.mjs`：增加对应回归测试。

“任务货格”与“机器人当前目的地”分别处理。例如出库任务 `R19-L3-C7-F1 → OUT-3` 的关联货格为货架上的取货源点；机器人拿到货后，其目的地是 OUT-3。保留旧机械臂绘图字段为空，避免误触发旧的跨架伸臂动画。
