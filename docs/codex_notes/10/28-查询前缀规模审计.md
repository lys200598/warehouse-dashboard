# 查询前缀规模审计

### 任务背景

完整周图谱持续增长。压力查询较早发起时，其可见知识水位可能尚未达到百万节点，需要逐请求核对规模，保留早期样本的真实覆盖范围。

### 关键结论

- `ops/source_size_at_queries.py`只读最终原始journal、查询索引、可选完整响应及最终物理对照报告，不接触Neo4j。
- 每个提交独立验证SHA、连续序号、run身份、完整100机器人状态和事件序号，然后累积该run在相应水位的去重节点。
- `WHRealState`共享`WHAgentState`节点；充电位等label共享对应位置节点，累计总数按节点身份计算。
- 每条查询绑定自己选择的`seq`，输出每轮最小/最大前缀规模及百万覆盖请求数。完整响应提供的实际graph head另行统计。
- 审计通过表示来源绑定和规模统计一致；每轮是否达到百万规模、并发和延迟分别报告。
- 13项独立测试通过。实际peak原始journal逐批计数得到首批8,435、最终32,520节点和1,500条机器人状态，与已验证图计数一致。

### 执行过的操作

```bash
bash run_in_lade.sh python ops/source_size_at_queries.py \
  --journal /absolute/path/to/final/journal.sqlite \
  --requests /absolute/path/to/original/requests.jsonl \
  --responses /absolute/path/to/original/responses.jsonl.gz \
  --comparison /absolute/path/to/week-physics-comparison.json \
  --output /absolute/path/to/new-source-size-audit.json
```

输出已存在时拒绝覆盖。最终来源节点数与物理对照报告的同run真实Neo4j去重计数、每label计数和最终水位逐项比较。

### 修改内容

- 新增`ops/source_size_at_queries.py`：逐批前缀计数、逐请求绑定、完整响应来源核对及每轮覆盖汇总。
- 新增`tests/test_source_size_at_queries.py`：13项小型正反例，包括早期水位不倒灌、父子label不重计、未来水位、损坏SHA、缺失提交、机器人缺失和最终图计数不符。
- 保持backend及正在运行的完整周生产者和原等待助手不变。

### 后续建议

完整周结束后，用最终原始压力文件执行本审计。只把`million_node_requests`覆盖的实际样本用于百万前缀性能结论，并保留其他阶段作为增长过程中的性能观测。
