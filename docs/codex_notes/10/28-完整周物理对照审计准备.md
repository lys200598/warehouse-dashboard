# 完整周物理对照审计准备

### 任务背景

完整七天任务正在分别运行历史授权模式与规则对照。需要在两个生产者自然结束后，核对最终物理状态、实际交接控制链和同一run的图谱规模，并保存可追溯证据。

### 关键结论

- 独立助手位于工作区上层`deployment/post-week-audit.py`，保持冻结backend及生产者文件不变。
- 助手等待首日暂停、恢复完成、规则完整周三个阶段退出0，再对最终输入执行审计。失败阶段会保留现场并停止，不自动重启仿真。
- 最终checkpoint按字段做规范化SHA比较。仅显式排除实验身份、知识提交/事件计数、历史模式统计、OS PID及三项主机墙钟计时；机器人电量、位置、任务、货物、库存和调度物理状态继续完整比较。
- 图谱去重节点、真实机器人历史状态分别计数。`WHAgentState`与`WHRealState`是同一节点的两个label，充电位也与对应位置节点共享身份。
- 11项小型独立测试通过。已完成高峰run的计数核对为32,520个实际去重节点、1,500条实际机器人状态，来源推导与Neo4j逐label计数一致。
- 本文件记录助手部署；完整周最终验收以`week-physics-comparison.json`、`control-source-audit.json`及各阶段原始日志为准。

### 执行过的操作

1. 读取`knowledge_runtime`、`real_scale`、图写入和检查点格式，明确逐批版本及共享label计数方式。
2. 运行`deployment/test_post_week_audit.py`，11项通过，包括缺失机器人、事件序号断裂、重复版本、SHA损坏和失败生产者停止等反例。
3. 使用已完成的`peak-current-v2`只读核对来源与图谱节点计数。
4. 在Pro6000启动`deployment/start-post-week-audit.sh`，该助手等待原生产者自然结束。

### 修改内容

- 新增`deployment/post-week-audit.py`：等待阶段、原始来源统计、物理字段对照、控制审计阶段记录及可选只读图统计。
- 新增`deployment/test_post_week_audit.py`：独立小型正反例测试。
- 新增`deployment/start-post-week-audit.sh`：载入既有私有环境并运行只读助手，保存独立退出码；不打印连接凭证。
- 仓库内生产backend源码保持不变。

### 后续建议

完整周自然结束后，读取最终报告和原始阶段日志；查询来源验真复用助手生成的完整`control-oracle`，继续完成真实读写混合查询的独立审计。有限测试中的最慢请求与硬实时保证分别表述。
