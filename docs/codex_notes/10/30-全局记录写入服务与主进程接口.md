# 全局记录写入服务与主进程接口

## 任务背景

用户要求开始开发全局记录写入进程，并向主进程提供接口。接口需参考图片要求：HTTP/JSON、数据创建/删除/一次性导入、单点查询及接口文档；同时遵循 wz 协作者的架构边界。

## 关键结论

- 新增独立 HTTP 服务 `backend.global_writer_api`，默认仅监听 `127.0.0.1:14284`；启动命令使用项目本地 `.venv`，不依赖相邻部署仓库。
- 14284 服务自身拥有有界队列和后台写入 worker；主进程接入只需调用 HTTP 接口，具体调用链由协作者处理。
- 新服务支持全局记录写入、逻辑数据集创建/删除、按 `import_id` 的一次性导入、Step/Handoff 单点查询和受确认字段保护的运行记录删除。
- 数据集接口管理的是逻辑命名空间 `GlobalRecordDataset`，不是物理 Neo4j 数据库，避免影响其他人的实例并兼容 Community Edition。
- C 套新增 `Step` 与 `Handoff`：主进程必须显式提交回执编号，`Step` 才会在编号数达到期望数量时更新 `Run.latest_step`；`Handoff` 保留交接双方、货物、任务、原因、地点与时刻。
- 未改动现有 4173 主进程调用链；接口保持独立，供协作者接入。
