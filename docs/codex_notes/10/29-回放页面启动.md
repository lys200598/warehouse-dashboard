- `14185` 是多运行回放服务，默认选中最新的 `visual-demo-20261028-160823`；也可以选择 `day1-history`。两者都不是 4173 的 `warehouse-3fafa0f3f4cb`。

- 若要让回放页显示 4173 的历史，需要给 4173 增加帧记录，或另跑一次带 `--frames` 的 V5 运行（那是独立 runId，轨迹也不等同 4173）。

## 回放是否需要单独服务

- 当前需要。4173 是实时服务，不写 `frames.sqlite`；回放页由 `backend.warehouse serve` 单独启动，读取某个 run 目录的 `latest.json`、`frames.sqlite`、`checkpoint.json`。
- 回放服务是只读的：不推进仿真、不写图谱、不修改 checkpoint。
- 一个回放服务只服务一个 `--output` 目录；不同 run 需要不同端口或重启服务。
- 右上角按钮默认指向多运行服务 14185；如果该服务未启动，按钮会连接失败。
- 若希望 4173 单服务同时提供实时和回放，需要给 4173 增加帧录制/回放接口，或做反向代理；这属于之前暂缓的改造。

## 4173 是否会留下回放记录

- 现在会。4173 默认每 5 模拟秒把当前快照写入 `data/local-runs/console-<runId>/`：
  - `frames.sqlite`：压缩帧，按模拟秒索引；
  - `latest.json`：最新 tick、elapsed、running、knowledge；
  - `checkpoint.json`：由 4173 快照合成的场景（货架/工位/机器人坐标）。
- 录制器是 `backend/console_replay.py`；主进程在 `backend/server.py` 的仿真循环中按间隔写入，不依赖 Ray Actor。
- 可用 `--replay-record-seconds` 调整间隔，`--replay-record-dir` 改目录，`--no-replay-record` 关闭。
- 写入失败不会中断仿真；错误显示在 `/api/health` 的 `replayRecord.error`。
- 回放服务 14185 会把正在写入的 console run 标记为“● 当前”，首次打开默认选择并每 5 秒刷新。
- 旧版 4173 进程如果未重启，仍不会写这些文件；需要重启（同 run 恢复时加 `--resume --allow-code-change`）。
