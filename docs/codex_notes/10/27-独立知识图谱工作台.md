# 独立知识图谱工作台

## 任务背景

仓库主页面无法直观看出知识图谱相关工作。需要参考 KG_Embodied 的能力展示方式，使用真实的后端接口把数据生成、Neo4j 图谱读写、任务追溯和机器人运行轨迹集中展示，同时不依赖仓库布局协作者的页面改动。

## 关键结论

- 新增 `kg.html` 独立工作台，地址为 `/kg.html`，不再把图谱功能隐藏在仓库运行页侧栏。
- 页面只读取后端 API 返回的 Neo4j 状态、数据集统计、任务和机器人轨迹；数据库不可用时会明确报出，未使用伪造成功状态。
- 工作台将闭环拆成 CSV 数据集、静态仓储图谱、运行态执行图谱和可追溯查询四个步骤。
- 图谱运行态新增 `ASSIGNED`、`CARRYING`、`COMPLETED` 与 `ABOUT_EXECUTION` 关系，补足机器人、执行和事件之间的语义关联。
- 任务追溯用于查看任务的静态关系、Execution 和事件；机器人追溯用于查看 AgentState 和事件时间线。
- 完整闭环测试要求：静态数据已导入、Neo4j 已连接、后端已用 `WAREHOUSE_NEO4J_WRITE_ENABLED=1` 运行过仿真。

## 执行过的操作

- 读取 `dist/kg.html`、`dist/styles.css`、`backend/warehouse_runtime_graph.py`、`backend/warehouse_graph_query.py` 和运行态图谱单元测试。
- 重写 `dist/kg.html` 为独立的图谱工作台。
- 扩展运行态 Neo4j 写入 Cypher 关系。
- 运行 `./.venv/bin/python -m compileall -q backend scripts`。
- 运行 `./.venv/bin/python -m unittest tests.test_warehouse_runtime_graph`，结果为 2 项通过。
- 运行 `git diff --check`，结果通过。
- 尝试 `node --check dist/app.js`；本机 Node 版本不支持项目既有的 optional chaining 语法，因此该检查无法作为前端语法结论，和本次修改无关。

## 修改内容

- `dist/kg.html`：新增独立工作台，包含数据集统计、Neo4j 连接状态、图模型、闭环检查、任务追溯、机器人追溯和事件时间线。
- `dist/styles.css`：增加独立工作台样式。
- `dist/index.html`：更新样式缓存版本，确保浏览器加载最新样式。
- `backend/warehouse_runtime_graph.py`：运行态写入新增机器人分配、携带、完成以及事件关联执行的图关系。
- `tests/test_warehouse_runtime_graph.py`：覆盖新增关系存在于写入 Cypher 中的断言。

## 后续建议

- 导入静态图谱并启动后端运行一次 100 机器人仿真，随后在 `/kg.html` 验证三个闭环状态均为绿色。
- 页面中的 Run ID 自动来自当前后端；若重启后端，要刷新页面后再查询机器人轨迹。
- 需要百万级演示时，使用既有运行态生成和导入脚本导入 `AgentState`，再在本页面展示实际计数和追溯结果。
