## 关键结论

- 项目定位是「100 机器人仓库仿真 + 时序知识图谱实验平台」，目标是跑通 `CSV 数据集 → 静态图谱 → 仿真 → 运行态图谱 → 回放/查询` 的可见闭环，并最终面向百万级图谱、100 智能体并发、端侧 <500ms 的研究指标。
- 当前存在三个互不等价的运行面：V5 批式仿真（`python -m backend.warehouse`，回放 14183）、4173 实时控制台（`python -m backend.server`，FastAPI + Ray 100 Actor）、14185 多 run 只读回放（`backend.replay_service`）。三者共享 Neo4j，但 `runId` 必须分开追溯。
- 代码分两条主线：4173 实时链路（`server.py` / `simulation.py` / `runtime.py` / `domain.py`）与 V5 知识实验链路（`wide/` / `scheduling_v5/` / `knowledge_runtime/` / `real_scale/` / `query_v2/` / `query_catalog/`）。两条链路目前尚未统一内核。
- 数据契约固定为 `layout.json` + `task-locations.csv` + `tasks.csv`（7 字段）+ `initial_inventory.csv` + `manifest.json`。基线布局 90×76m / 36 架 / 1728 货位；协作者扩展布局 100×90m / 40 架 / 1920 货位，两者并存、不可混用。
- 图谱分静态（`Warehouse/Zone/Rack/Location/Dataset/Goods/WarehouseTask`）与运行态（`Run/Robot/AgentState/Execution/RuntimeEvent`）；本地 `journal.sqlite` 用 `seq/commit_seq` 表示知识提交水位。
- 工作区当前有 10 个已修改文件 + 6 个未跟踪文件，主要是 4173 回放录制、多 run 回放服务、统一启动脚本和布局迁移，均未提交；文档中「569 项回归」针对旧提交，不代表当前工作树。
- 服务目前实际在跑：4173（Ray 100 worker、`csv-dataset`、`robot-actors` 写图、health=ok）、14185（多 run 回放）、项目 Neo4j（47474/47687）、Ray head（26380）。Neo4j 中已有约 1046 万 `AgentState`、23 个 `Run`、6912 个 `WarehouseTask`。

## 一、项目定位与目标

- 研究目标（见差距分析笔记引用的项目指标）：边端具身智能的多设备协作知识管理，向量/图/时序统一，支持 ≥100 智能体节点协同查询，百万级图数据下端侧查询 <500ms。
- 平台目标：用 100 台仓储机器人承载上述研究，形成可复现、可追溯、可回放的闭环。
- 当前阶段优先级（`AI_PROJECT_HANDOFF.md`）：数据集 → 静态图谱 → 4173 实时执行/写图 → 图谱查询。压测和最终优化不属于当前代码交接阶段。
- 明确不包含：LLM 调度/自然语言控制不在本分支交付范围。

## 三、数据与图谱闭环

```text
layout.json + task-locations.csv + tasks.csv + initial_inventory.csv + manifest.json
        │ 校验 SHA/ID/容量/时间/库存依赖
        ▼
静态图谱导入（Neo4j）：Dataset/Warehouse/Zone/Rack/Location/Goods/WarehouseTask
        ▼
V5 仿真（backend.warehouse run）  或  4173 实时（backend.server）
        │ 派单/能量/交通/取放/充电/交接
        ├─ journal.sqlite（提交水位） / checkpoint.json（恢复）
        ├─ frames.sqlite（回放帧，V5/4173）
        └─ 运行态图谱：Run/Robot/AgentState/Execution/RuntimeEvent
        ▼
14183 / 14185 回放    4173/kg.html 追溯查询
```

- 任务类型只有 `INBOUND` / `OUTBOUND`；`release_time` 决定放行顺序。
- 静态 `WarehouseTask` 与运行态 `Execution` 关联的前提是：4173 的 `WAREHOUSE_NEO4J_PACKAGE_DIR` 与 `--simulation-dataset-dir` 指向同一个已导入数据包，且任务保留原始 `T-*` ID。
- 图谱合同详见 `docs/graph-contract-v1.md`；数据合同详见 `docs/dataset-contract/README.md`。
