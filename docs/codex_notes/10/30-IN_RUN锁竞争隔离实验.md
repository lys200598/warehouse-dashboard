### 关键结论

- 假设的核心得到直接证据支持：原写法的历史事务等待同一个 Run 的 `NODE_RELATIONSHIP_GROUP_DELETE:EXCLUSIVE` 锁，资源 ID 与该场 Run 的内部 ID 对应；移除历史关系后该竞争显著消失，恢复原写法后再次出现。
- “每步都 MERGE Robot→Run”不符合当前代码：机器人注册后已走 `_UPDATE_ROBOTS_ONLY`。瓶颈主要在历史采样，普通步基本不变；本实验不需要百万度数节点就能复现争用。
- 最终修复保留所有 IN_RUN，不改图谱查询契约：历史节点唯一 ID 的 MERGE 仍保留，只有创建该节点的输入行用 CREATE 建边，并在同事务移除行编号标记。失败整体回滚，重放不重复建边。
- 100 台批写均值降低 66.3%，约为原来的 1/2.97。这是写入阶段改进，不是整步或查询吞吐提升倍数。
- ABBA 四轮各 400 步、最终兼容修复一轮 400 步均通过：派单与内存参照一致；每轮 401 个完整 Step，各 100 个真实回执；最终修复的节点数、IN_RUN 数与查询结果同 A1；清理均为 0。
- 修复同时通过同批重复事件、重复机器人记录及跨调用重放检查；修复了两个读取路径已有的 importing-WITH 语法错误，并补入真实 Neo4j/HTTP 查询验证。
