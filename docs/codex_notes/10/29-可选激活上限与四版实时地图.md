# 可选激活上限与四版实时地图

### 任务背景

用户希望为新版实时入口增加可省略的启动参数，临时观察 50 台激活效果；随后要求同时打开已有多个版本的仓库实时仿真。

### 关键结论

- 新入口支持 `--max-active-robots 50`。省略参数时不覆盖数据集配置，现有配置默认仍为 100 台；值须为 1～100 的整数。不把 50 写入默认 JSON。
- 在线机器人总数和物理障碍仍为 100。上限控制同时拥有执行作业的机器人，排队、取放、返航、充电、换电均占名额；同一机器人衔接下一任务不额外占位。满额不创建第 51 个接力执行者，也不把普通限流记成寻路失败。
- 当前中型试验已通过真实 API 与浏览器核对：50 台激活、50 台待命，持续移动并完成任务，启动命令实际包含该参数。此前 14192 的 100 台运行及冻结源码保持不动。
- 四个可直接使用新版引擎的地图都已开启独立实时仿真，统一激活上限 50、速度 1.5m/s、A1/R2/X3=15/15/70。初始待命段以 20 倍目标速度推进，观察到工作后已恢复 1 倍。
- 三个额外地图预览使用 journal/rules，持续执行真实运输并保存本地日志；中型 14193 保留 required/Neo4j 与 100 个独立机器人 I/O 进程。各页面不能作为同一条件下的图谱性能对照。
- 每个地图均使用已验证兼容的 1728 任务输入，保留任务时间约束。宽松版从已有 preserve 输入逐字节迁移 CSV 并验证新场景身份；balanced/medium/large 使用各自的覆盖映射输入。货位引用并非完全相同，页面时钟也不同，不直接比较当前完成数来评价性能。
- 原 60×48m、24 充电位设计属于旧加载合同；未将它伪装成新版引擎的实时地图。本轮开启的是下面四个兼容版本。

### 后续建议

同一条新版启动命令末尾增加 `--max-active-robots 50` 即为本次用法；去掉该参数并启动新进程即可恢复数据集默认值。每轮已使用的值保存在各自 run 身份中，不能用不同上限冒充同一轮续跑。

先比较布局、机器人密度与行驶距离。若需要比较 50/100 台的完成率、晚点和能耗，应使用相同地图、输入、图谱模式、起始条件和完整运行窗口另做对照；当前四个页面用于观察效果。
