# 图谱回放详情可视化

### 任务背景

用户反馈图谱运行态回放只能看到绿色点和汇总，无法了解每个点实际代表哪台机器人、当前任务和运行状态；随后确认地图点选交互不适合作为该功能的主要呈现形式。

### 关键结论

- 绿色点此前只是工作中机器人的无标签位置点，详情只存在于不明显的浏览器悬浮提示中。
- Neo4j 回放接口已经返回机器人编号、阶段、电量、坐标、任务和货物字段，无需增加后端接口或模拟数据。
- 回放现在默认选中一台机器人，并可点击任意点切换详情。
- 详情卡清楚显示所处 tick、位置、电量、任务和货物；选中的点有黄色描边。
- 增加绿色/蓝色/灰色图例，分别对应工作中、充电、待命。
- 为解决待命点点击反馈不明显的问题，选中结果同时显示在地图左上角，点击目标扩大至 13px，选中点扩大至 18px。
- 最终将地图式回放改为文字化“运行态追溯”：按 Run ID、可选 tick、可选机器人编号查询并逐行展示状态。
- 查询改为取请求 tick 之前最近一次 `AgentState` 采样，避免采样间隔造成无结果的误解。

### 执行过的操作

- 阅读 `dist/kg.html` 的回放渲染逻辑与 `dist/styles.css` 的回放样式。
- 核对 `backend/domain.py` 中真实机器人阶段值：`toPick`、`toRack`、`picking`、`placing`、`returning`、`charging`、`idle`。
- 未连接 Neo4j、未写入或修改任何运行态数据。
- 执行 `./.venv/bin/python -m unittest discover -s tests`，36 项测试通过。
- 执行 `./.venv/bin/python -m compileall -q backend` 与 `git diff --check` 验证后端和补丁格式。

### 修改内容

- `dist/kg.html`：将回放点改为可点击的按钮，新增选择状态、中文阶段名、机器人详情卡和地图内选中信息条。
- `dist/styles.css`：新增可点击点、较大的选中态、状态图例、详情卡和地图内选中信息条样式。
- `backend/warehouse_graph_query.py`：新增运行态文字追溯的有界查询，返回请求 tick 与实际采样 tick。
- `backend/server.py`：新增 `GET /api/kg/warehouse/runs/{run_id}/runtime-trace` 接口。
- 页面现已移除地图点位和拖动回放控件，改为运行态查询表单和文字记录列表。

### 后续建议

- 重启/刷新前端服务后打开 `kg.html`，拖动 tick 并点击任意机器人点验证详情。
- 若要进一步查看该机器人的长期任务链路，可把详情中的机器人编号带入下方“机器人追溯”卡查询。
