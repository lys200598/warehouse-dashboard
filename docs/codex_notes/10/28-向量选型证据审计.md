# 向量选型与服务端提速原型证据审计

### 任务背景

统一发布前核对向量质量、默认路线和提速原型，帮助首次接触项目的同学理解数据与检索的关系。范围限于证据审计和文档，不修改后端、默认查询、共享环境或七天冻结源码。

### 关键结论

- 正式`similar_history`默认17D有界客户端精确检索，原32D HNSW工程接口显式保留。
- 12例完整历史前缀的表示质量与默认60提交窗口的覆盖分开评价；Precision@5为0.8167/0.4333，标签是结构相似性。
- 服务端精确原型48条串行请求逐项来源和结果顺序通过，24次/方法均值230.153ms/146.898ms；保留1121.801ms首冷和1/24超500ms。
- 最后12次/方法暖重复轮服务端约2.20倍速度；100客户端、持续写入、正式API兼容仍需专项验收。
- 两个证据包清单内19/10个数据文件SHA与ZIP CRC通过；包含清单后ZIP分别20/11项。
- 任务CSV保持原合同；向量来自运行中真实状态，电量扰动与协作场景由独立配置生成。
