# 机器人与任务追溯增强

### 任务背景

当前知识图谱页面只能显示机器人或任务关联记录的数量，无法直接说明某台机器人在何时、何地、执行了哪条任务，也无法完整展示任务的分配、取货、完成过程。本次仅优化机器人和任务的图谱追溯，不调整仓库布局、回放交互或性能压测。

### 关键结论

- 机器人追溯改为读取 Neo4j 中截至指定 tick 的最近状态，而不是仅统计子图节点数。
- 机器人结果同时给出位置、阶段、当前任务、采样滞后、最近轨迹、已关联执行任务和运行事件。
- 任务追溯直接展示货物、起点、终点，并按机器人展示已分配、已取货、已完成三个生命周期 tick。
- 所有读取仍是固定、带上限的 Neo4j 预置查询；页面不接收任意 Cypher。
- 页面中 tick 为 0 时，机器人追溯表示读取最新已写入状态；输入正数时表示读取该 tick 或之前的最近采样。

### 修改内容

- `backend/warehouse_graph_query.py`：新增并完善 `robot_trace_context` 的有界查询；将默认 tick 0 定义为“最新状态”，避免页面初始值错误地只查 tick 0。
- `backend/server.py`：已提供 `GET /api/kg/warehouse/runs/{run_id}/robots/{robot_id}/trace`，供页面读取聚合后的机器人上下文。
- `dist/kg.html`：任务卡片新增生命周期/事件时间线；机器人卡片改用新追溯接口展示实际状态、任务和事件；预置查询按钮同步为“机器人上下文”。
- `tests/test_warehouse_graph_query.py`：覆盖机器人追溯的 tick 范围、轨迹顺序、执行任务、事件和默认最新状态语义。

### 后续建议

- 重启后端后，以开启 `WAREHOUSE_NEO4J_WRITE_ENABLED=1` 的运行批次产生数据，再在 `kg.html` 输入该 Run ID 验证机器人和任务链路。
- 若要追溯更久以前的状态，调整状态采样间隔或在后续由性能负责人增加分区/归档策略；本次不改变写入频率。
- 任务没有运行记录时属于数据尚未写入，不应在页面伪造执行链路。
