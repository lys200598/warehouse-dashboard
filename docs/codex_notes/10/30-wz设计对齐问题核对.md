# wz 设计对齐问题核对

## 任务背景

用户要求重新读取 `wz/warehouse-design` 分支的 `docs/design/LYS_ALIGNMENT_QUESTIONS_20261030.md`，并判断其中列出的九项对齐问题与当前整合分支实现的关系。

## 关键结论

- 指定文档已在 `wz/warehouse-design` 的最新提交 `93bcfc5` 中可读取。
- 当前分支已经具备 CSV 驱动的 V5 仿真、4173 页面、Ray 运动 Actor、机器人 C 套图谱写入和独立全局写入进程；但这些仅覆盖了目标架构的一部分。
- 当前 `MotionActor` 是无状态的：主进程每 tick 传入计划段和时间，Actor 只计算该秒的位置；位置、电量、任务、计划与库存的权威仍在主进程。问题 5 所描述的“有状态机器人 Actor”尚未实现。
- `--robot-graph` 下，机器人 Actor 已自行写入 `Robot`、`AgentState`、`Execution`、`RuntimeEvent`；但机器人还不会自主读取 C 套图谱作为决策上下文。
- 全局写入进程已写 `RunStat`、`DispatchState`、`Assist` 和无归属机器人的全局事件；尚未写逐步完成屏障 `Step(t)`，也未维护 `Run.latest_step`。
- `cargo_handoff` 的完整交接事实尚未在 C 套闭环：机器人事件转换会丢失 `donor_id`、`receiver_id`、`reason` 等字段；现有 `Assist` 只能保存协作期间的摘要，不能替代可追溯的交接事实。
- `Execution-[:ASSIGNED_TO]->Robot` 是只增不删的历史参与关系，当前查询没有明确区分“当前负责人”和“历史参与者”；按历史 tick 查询时，执行记录也未统一作时间截断。
- 当前规则调度仍读取主进程内存台账，这是 LaDe 的正常规则调度方式；`KG_STATE_SOURCE=neo4j` 没有实现。应先确认架构图绿线是否一定要求“图谱回读派单”，不要将它和“机器人查询决策上下文”混为同一能力。

## 后续建议

建议对文档中的九项问题给出如下统一答复，并据此拆分后续开发。

| 问题 | 当前结论与建议 |
|---|---|
| 1 标记处理 | 知悉并同意保留在主进程。主进程应在处理交接标记后，把标准化的跨机协作事实投递给全局写入进程。 |
| 2 图谱读取含义 | 建议定义为两条独立可选能力：A 为 `memory/neo4j` 状态回读一致性模式；B 为每台机器人读取自身决策上下文。规则调度默认内存，B 必须补齐；A 可作为可切换验证模式，而非立刻取代内存。 |
| 3 交接记录 | 采用 `Handoff` 或扩展 `Assist` 的不可变事实记录：`run_id`、tick、task、goods、donor、receiver、reason、位置、事件 ID；同时连接两台 Robot、Execution/Task。传递方式应使用主进程到全局写入进程的有界队列，保持现有独立进程边界。 |
| 4 当前负责人/历史口径 | `ASSIGNED_TO` 明确为历史参与；增加或明确 `Execution.current_robot_node_id`（或 `current_robot_id`）为当前负责人。图谱查询必须在 `tick` 查询中按 `updated_tick <= tick` 限制执行状态，或将执行状态版本化。建议由知识图谱模块修改。 |
| 5 改写 ray_medium | 同意由 wz 改写。当前 Actor 与目标不符，迁移后应保留现有启动参数、C 套标签、`graph_state_interval` 和回归基准。 |
| 6 实验隔离 | 推荐 Neo4j 各自独立实例；Ray 至少使用可配置 namespace，当前硬编码 `warehouse-medium-ray` 不足以隔离。对百并发写入应显式配置并验证连接池，而非依赖默认值。 |
| 7 Step 屏障 | 同意由全局写入进程负责。新增 `Step`（或 `RunStep`）和 `Run.latest_step`，仅在收齐该 tick 的机器人回执/写入确认后推进，查询以它作为完整帧边界。 |
| 8 决策上下文 | 同意先不改变规则派单，以保证派单基准不变；但先实现机器人真实的 C 套上下文读取与观测指标，为后续接入决策做准备。 |
| 9 机器人各自写入 | 同意。保留每机器人独立、幂等、可重试写入；但当前事件游标会在写入确认前前移，失败事件可能丢失，需在有状态 Actor 改造时改为“确认后推进游标”。 |

推荐实现顺序：先合入 wz 的有状态 Actor 与派单基准；随后补交接事实、Execution 时间语义、Step 屏障；再实现机器人 C 套查询和可选 `KG_STATE_SOURCE=neo4j` 一致性模式；最后基于 C 套实际查询做 100 路/百万节点验收。
