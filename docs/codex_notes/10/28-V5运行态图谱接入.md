### 任务背景

项目需要以协作者的 V5 仓库布局、100 机器人策略和充电逻辑作为物理运行权威，同时继续使用当前项目的 Neo4j 静态图谱、运行态追溯和知识图谱工作台。

### 关键结论

- V5 已经是数据集、布局、交通、库存、充电和低电协作的唯一运行来源，不能将其替换为旧 4173 控制台的模拟状态。
- 运行态图谱应在 V5 的一致性提交边界写入，而不是从前端猜测机器人位置或任务状态。
- 新增适配器只投影 V5 真实状态到 `Run`、`Robot`、`AgentState`、`Execution`、`RuntimeEvent`；不会修改 V5 的调度或充电决策。
- 开启 `WAREHOUSE_NEO4J_WRITE_ENABLED=1` 后，V5 运行与 `kg.html` 使用相同的 Run ID 和数据集身份。

### 执行过的操作

- 阅读 V5 调度器、运行帧、提交循环、充电/任务事件和 V5 图谱写入实现。
- 为 V5 状态实现到通用运行态图谱格式的转换。
- 在 V5 journal 提交后追加图谱写入，保证投影对应已提交的状态与事件。
- 运行运行态图谱与 V5 CLI 测试，检查 Python 编译和补丁格式。
- 修复 Neo4j 5.26 对 `FOREACH` 条件写入的 `CASE` 括号语法兼容问题。
- 进一步移除运行态、静态图谱和 V5 历史图谱中的条件 `FOREACH` 写法，改为 Python 侧分批与 Cypher `MATCH` 关系写入，避免 Neo4j 5.26 解析差异。

### 修改内容

- `backend/warehouse_runtime_graph.py`：新增 `v5_runtime_snapshot`，映射 V5 的 100 个真实机器人、任务、货物、充电事件及位置。
- `backend/knowledge_runtime/runner.py`：在设置环境变量后构建图谱写入器，并在每个 V5 提交点写入运行态图谱。
- `tests/test_warehouse_runtime_graph.py`：增加 V5 适配器映射测试。
- `backend/warehouse_graph.py`、`backend/knowledge_graph.py`：将可选关系拆为明确的批量写入，保证静态图谱导入和 V5 Neo4j 历史模式也不依赖条件 `FOREACH`。
- `dist/v5/wide.js`：在协作者的 V5 实际回放页添加“知识图谱追溯”入口，跳转到你的图谱工作台。
- `启动与图谱数据操作手册.md`：补充 V5 运行时开启运行态图谱投影的变量与边界说明。
- 启动文档第 8 节改为图谱工作台只读模式，防止旧 4173 控制台向 V5 专用图谱混写非 V5 运行态。
- 为旧控制台检查点兼容已移除的 `dataset_path` 字段；图谱工作台仍默认使用新的暂停检查点而不是恢复旧实验。
