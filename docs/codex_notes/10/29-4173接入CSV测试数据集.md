# 4173 接入 CSV 测试数据集

## 任务背景

4173 原先只使用后端内置的 `TK-*` 演示任务。用户要求开始接入已生成的仓储 CSV 数据集，使实时搬运和 Neo4j 运行态图谱以同一份业务任务、货物、库存和货位为输入。

## 关键结论

- 4173 新增 `--simulation-dataset-dir`，目录中的 `tasks.csv` 和 `initial_inventory.csv` 成为实时派单来源。
- 数据集中的真实 `T-*` 任务 ID、货物 ID、任务类型、来源/目标位置和释放时间会保留到 4173 的任务、事件和运行态图谱中。
- 支持 `INBOUND` 与 `OUTBOUND`：入库从入库台取货后上架，出库从源货位取货后送往出库台。
- 初始库存会投影到 4173 的实时控制地图；完成入库/出库任务会更新对应投影货位状态。
- 4173 的交通与运动内核仍不同于 V5，因此实时位置轨迹不能替代 14183 的 V5 历史回放。
- 页面标题和库位统计会显示 `CSV DATASET` / `CSV 测试数据集`，用于区分演示任务模式。

## 修改内容

- `backend/server.py`：添加数据包目录配置、CSV 加载和 `--simulation-dataset-dir` 参数。
- `backend/simulation.py`：增加按数据集释放时间派单、位置投影、初始库存投影、入/出库完成后的库存更新及任务源状态输出。
- `backend/domain.py`：机器人状态机识别入库和出库取放语义。
- `dist/app.js`：页面运行标识和库位统计显示任务源是 CSV 数据集还是演示任务。
- `tests/test_live_dataset_source.py`：覆盖真实数据集任务 ID 与出库语义的派单路径。
- `启动与图谱数据操作手册.md`：补充 4173 数据集模式的环境变量和启动参数。
