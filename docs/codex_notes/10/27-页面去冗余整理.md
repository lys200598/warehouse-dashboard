# 页面去冗余整理

## 任务背景

用户反馈当前页面信息重复、入口过多，需要在保留仓库运行与知识图谱能力的前提下整理界面。

## 关键结论

- 首页此前同时存在顶部图谱页签、右侧图谱追溯卡和独立图谱页，属于同一能力的重复入口。
- 首页现只展示仓库实时调度，并在顶部提供唯一的“知识图谱工作台”入口。
- 图谱查询统一收敛到 `/kg.html`，避免调度信息和数据管理信息争夺同一屏幕。
- 独立图谱页由四块重复说明收敛为三项状态：生成数据、Neo4j 写入、可追溯状态。
- 任务追溯和机器人追溯仍被保留，是图谱闭环的实际操作入口。

## 执行过的操作

- 阅读并梳理 `dist/index.html`、`dist/kg.html` 和 `dist/app.js` 中的图谱入口和绑定逻辑。
- 删除首页的图谱页签、首页图谱工作台、侧栏图谱追溯卡及其无效前端请求。
- 运行 `grep` 排查已删除元素的残留引用。
- 运行 `git diff --check`。
- 运行 `./.venv/bin/python -m unittest discover -s tests`，26 项通过。

## 修改内容

- `dist/index.html`：首页增加独立图谱页跳转，删除重复图谱展示区域，并更新静态资源缓存版本。
- `dist/app.js`：删除只服务于首页重复图谱区域的刷新、任务列表和追溯绑定代码。
- `dist/kg.html`：合并重复流程/模型说明，保留紧凑状态概览和两种追溯查询。
- `dist/styles.css`：调整独立图谱页概览为三列布局，并增加简短关系说明样式。

## 后续建议

- 刷新浏览器后，仓库调度页与知识图谱页分别打开检查；缓存版本已更新。
- 若还要继续压缩仓库首页，建议下一步只评估左侧“利用率”和右侧“任务队列”的信息密度，不动核心地图和机器人详情。
