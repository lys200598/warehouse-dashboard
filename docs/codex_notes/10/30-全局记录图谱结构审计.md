# 全局记录图谱结构审计

日期：2026-10-30

## 任务背景

排查当前知识图谱：能否写入全局记录，字段是否完备，能否支撑目标架构中的全局统计、跨机协助、调度状态查询。

> 修复进展（2026-10-30）：本文是修复前审计。当前已补 `RunStat(id)`/`Assist(id)`/`DispatchState(id)` 唯一约束、`RunStat.commit_seq` 与 durable/mirrored/generated/writer 字段、`Run` dataset/scene/tasks/config identity、`Assist` 节点、`DispatchState`（active jobs/pending/ports/robots/tasks）、`run_stats/global_events/assists/dispatch` 查询 API 和 kg.html 全局面板；仍未接 `KG_STATE_SOURCE=neo4j` 的读取调度路径。下文“当前结构”保留修复前基线，修复后的字段见“修复进展”节。

## 关键结论

- **能写入**：`GlobalWriterProcess` 已向 Neo4j 写 `Run`、`RunStat`、全局 `RuntimeEvent` 和 `IN_RUN` 关系；`Run`/`RuntimeEvent` 有唯一约束，`RunStat` 有 `(run_id,tick)` 索引。
- **字段不完备**：
  - `Run` 只有 backend/robot_count/max_active/status/updated_tick/global_stats_json，没有 dataset/scene/config/durable seq；
  - `RunStat` 只有 tick/elapsed/status/counts/tasks/assists/metrics/inside，没有 commit_seq、durable/mirrored seq、writer errors/dropped；
  - 跨机协助只有 `RunStat.assists_json`，没有 `Assist` 节点/关系，无法按 donor→receiver→task 追溯；
  - 全局 `RuntimeEvent` 只写 `robot_id=null` 的事件；V5 的 `assistance_*` 事件带 donor robot_id，会被 per-actor writer 写，global writer 不会形成全局协助事件；
  - 没有 `DispatchState`，`KG_STATE_SOURCE=neo4j` 无法实现。
- **查询层不配套**：`Neo4jWarehouseGraph` 没有 `run_stats()`/`global_events()`/`assists()`；`kg.html` 没有全局统计面板。数据只能 raw Cypher 查。
- **约束/建模**：`RunStat` 未加入 `RUNTIME_SCHEMA`，只有 writer 建的索引，没有唯一约束；`RunStat.id` 为 `{run}:stat:{tick}`，同一 tick 多次提交会覆盖。
- **测试证据**：`wh-live-20261030T013257Z-9ea64a90` 有 28 个 `RunStat`；`Run`/`RunStat` 属性见下；全局事件 0 条（该测试没有全局事件，且 assist 走机器人 actor）。

## 字段完备性评估

| 目标内容 | 当前字段 | 结论 | 缺口 |
|---|---|---|---|
| Run 身份 | id、backend、robot_count、max_active、status、updated tick | ◐ | 缺 dataset_id、scene/tasks/config hash、started/finished、owner |
| 全局 KPI | RunStat counts/tasks/metrics/inside | ✅ | 只有 JSON 字符串，无图属性 |
| 提交顺序 | tick | ◐ | 缺 commit_seq/durable_seq/mirrored_seq；同 tick 覆盖 |
| 跨机协助 | assists_json | ◐ | 无 Assist 节点、donor/receiver/task 关系、起止 tick/结果 |
| 全局事件 | RuntimeEvent（robot_id=null） | ◐ | assist 事件通常有 robot_id，未进入全局 writer |
| 调度状态 | `DispatchState` | ✅ | 已写 active jobs/pending/ports/robots/tasks；主进程读取 KG_STATE_SOURCE 未接 |
| 写入健康 | snapshot runtime.globalWriter | ◐ | errors/dropped 未持久化到图 |
| 配置/输入审计 | 无 | ✗ | 无 dataset/scene/tasks/config identity |
| 查询接口 | 无 | ✗ | 无 run_stats/global_events/assists API；kg.html 不展示 |

## 风险

1. `RunStat` 无唯一约束，并发/重复提交可能产生重复 stat；当前 MERGE id 可避免一部分，但缺 schema 保证。
2. `RunStat.id` 只含 tick，同 tick 多次 `_persist` 会覆盖，丢提交历史。
3. 全局协助只有 JSON，无法做图查询“谁协助谁、跨机关系、成功率”。
4. 全局事件可能为空：assist 事件的 `robot_id` 是 donor，global writer 只写 `robot_id=None`，因此跨机协助不会作为全局事件落图。
5. 没有 query API，写入后 kg.html 看不到，容易被误判为“没写”。
6. 无 `DispatchState`，主进程无法按目标架构从 Neo4j 读调度状态。

## 建议修复顺序

### P0：让全局记录可建模、可追溯

1. `RUNTIME_SCHEMA` 增加 `RunStat(id)` 唯一约束。
2. `RunStat` 增加 `commit_seq`，id 改为 `{run}:stat:{seq}`（或保留 tick + seq），避免同 tick 覆盖。
3. `RunStat` 增加 `durable_seq`、`mirrored_seq`、`generated_at_ms`、`writer_errors`、`writer_dropped`。
4. `Run` 增加 `dataset_id`、`scene_sha256`、`tasks_sha256`、`config_json`、`started_at_ms`、`finished_at_ms`。
5. `Run -[:USES_DATASET]-> Dataset`（有 dataset_id 时）。

### P1：跨机协助与全局事件

1. 新增 `Assist` 节点：`id, run_id, donor_id, receiver_id, task_id, start_tick, end_tick, reason, status, duration_ticks`。
2. `Assist -[:IN_RUN]-> Run`、`Assist -[:DONOR]-> Robot`、`Assist -[:RECEIVER]-> Robot`、`Assist -[:ABOUT_TASK]-> WarehouseTask`。
3. `RunStat` 保留 assists_json 作为快照；`Assist` 作为规范追溯结构。
4. 全局 `RuntimeEvent` 增加 `severity、source、seq、assist_id、details_json`；明确哪些事件允许 robot_id 为空。

### P2：查询与调度状态

1. `Neo4jWarehouseGraph` 增加 `run_stats(run_id)`、`global_events(run_id)`、`assists(run_id)`。
2. `ops/warehouse_live.py` 增加 `/api/kg/warehouse/runs/{run}/stats`、`/assists`。
3. `kg.html` 增加“全局统计/跨机协助”面板。
4. 新增 `DispatchState`（active jobs、队首、port/queue 压力）后接 `KG_STATE_SOURCE=neo4j`。
