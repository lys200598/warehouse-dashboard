# 逻辑边界与动态工位绑定实现

## 任务背景

数据集原来用七字段中的source_id/target_id固定具体IN/OUT口。用户希望数据描述进出仓任务，由仿真选择现有工位，比较是否能减少入口热点和晚点。本实现保持地图、八个IN/八个OUT、每IN口六件、速度、期限及库存/能源/避碰门不变。

## 关键结论

- 新数据仍为七字段：入库source_id可为INBOUND，出库target_id可为OUTBOUND，货架端点保留原值。
- manifest使用boundary_routing声明warehouse-logical-boundaries-v1；运行需显式port_selection_policy=balanced。默认fixed继续接受旧具体端点，遇逻辑数据明确拒绝。
- 入库在实际准入前绑定物理口；出库在实际发布时绑定物理口。绑定后固定，货物持有者仅在原received/picked/placed事件中改变。
- balanced模式保留所有任务的plan_source_id/plan_target_id及resolved字段；实际source_id/target_id供原物理引擎继续使用。固定端点在balanced中仍固定，不被强制重分配。
- 固定CSV对比400步，原fixed和显式balanced的机器人、货物、全部事件及任务物理投影一致；新增计划标签单列。
- 11项单测覆盖转换、声明、准入、发布、不可重绑、恢复、未来隔离、地图迁移和懒处理；完整峰值与真实图谱联合验收由主任务在冻结树中执行。

## 执行过的操作

读取wide数据/运行、V2准入与恢复、V5调度和库存双向校验接点。新增独立转换工具及纯绑定模块；实际执行19任务样例、恢复继续与400步固定数据兼容对照。日志在本地research/free-ports-local-test-frozen.log、research/free-ports-fixed-compatibility-final.log；代码SHA在research/free-ports-owned-sha-final.json。

## 修改内容

- backend/wide/free_ports.py：已发布状态评分、一次绑定、来源事件、计划与实际端点断言。入库评分综合空闲兼容机器人到口ETA、口到货架距离与已有暂存数；出库评分综合货架到口距离与已发布未完成出库负载。所有选择只指导调度，原执行门继续决定实际可行性。
- backend/wide/sim.py：新增fixed/balanced配置、初始化计划标签、显式release与inventory hook。fixed路径直接调用原实现。
- backend/wide/data.py：只有正确版本声明才接收逻辑marker；逻辑数据换图时保留CSV期限，拒绝根据未知具体口重算参考期限。
- backend/scheduling_v5/invariants.py：未绑定IN仅允许scheduled/waiting；未绑定OUT仅允许scheduled。进入准入/分配/运输等状态后仍要求实际物理口。
- ops/convert_logical_boundaries.py：创建新目录，把边界端点改为逻辑marker；保留ID、货物、时间、货架端点和初始库存字节，记录原件SHA。
- tests/test_free_ports.py：转换及运行契约验证。另把OUT负载扫描推迟到真正有逻辑OUT发布时，全口满不进行机器人评分，避免空tick扫描完整历史。

例如CSV中的INBOUND→R36-L2-C1-F2在1200秒准入时选中IN-7：plan_source_id仍是INBOUND，source_id/resolved_source_id成为IN-7，source_bound_at=1200，并有唯一boundary_port_bound来源事件。received随后才把货权记到IN-7；逻辑区没有被冒充为实际货物位置。

转换入口：

```bash
bash run_in_lade.sh python ops/convert_logical_boundaries.py \
  --scene data/layouts/expansion-candidates/balanced/layout.json \
  --source /absolute/fixed-dataset --output /absolute/new-logical-dataset --role both
```

运行使用原统一入口和配置JSON；加入port_selection_policy=balanced。固定口与逻辑口是不同场景输入，CSV SHA分别保存，比较时保持原件并列出变更范围。
