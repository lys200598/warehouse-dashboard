# 知识图谱管理界面入口恢复

日期：2026-10-29
当前页面：`http://127.0.0.1:4173/`（medium 120 live）
知识图谱页：`http://127.0.0.1:4173/kg.html`

## 一、先判断：这个功能是什么

这个页面是 **`dist/kg.html`「仓储知识图谱工作台」**，不是 120 页面底部的「共享知识与历史查询」面板。

- 标题：`仓储知识图谱工作台`
- 数据源：项目 Neo4j 的静态图谱 + 运行态图谱
- 依赖接口：`/api/kg/warehouse/health`、`/dashboard`、`/tasks`、`/tasks/{id}/trace`、`/runs/{runId}/robots/{robotId}/trace`、`/runs/{runId}/runtime-trace`、`/query-presets/*`
- 这些接口原来只在 legacy `backend.server` 中实现，medium live `ops/warehouse_live.py` 没有；120 页面又是从 wz 复制的页面，天然没有 `kg.html` 和跳转入口。
- 所以现象不是「页面被删了」，而是 **medium 页面切过来后，kg.html、入口和 API 都没有一起迁移**。

## 二、本次改动

1. **复制页面**
   - `dist/kg.html` → `dist/medium/kg.html`
   - 页面里的「← 返回仓库运行页」仍然指向 `/`，即返回 medium 120 页面。

2. **补样式**
   - 把 `dist/styles.css` 中 `.kg-*` 相关规则追加到 `dist/medium/styles.css`，避免 kg 页面无样式。

3. **右上角入口**
   - `dist/medium/index.html` 顶部右侧新增：
   ```html
   <a class="button ghost graph-link" href="./kg.html" title="打开仓储知识图谱工作台">知识图谱工作台</a>
   ```
   - 位置在「回放页面」左侧，和 legacy 页面一致。

4. **medium live 增加 kg API**
   - `ops/warehouse_live.py` 增加 `Neo4jWarehouseGraph` 实例（从 `WAREHOUSE_NEO4J_*` / `NEO4J_*` 环境变量读取连接信息）。
   - 新增 `/api/kg/warehouse/*` 路由，调用 `backend.warehouse_graph_query` 的只读查询；未配置 Neo4j 时返回 503，而不是 404。
   - 关闭服务时关闭图驱动。

5. **修复任务列表慢查询**
   - `backend/warehouse_graph_query.py` 的 `task_list` 原来先对全部任务做 `OPTIONAL MATCH Execution`，在 Neo4j 大数据量下会卡住。
   - 改为先按 `release_time` `LIMIT` 再 optional match；实测 3 条任务约 **321ms**。

## 四、边界

- 当前 medium live 用 `--knowledge-backend journal`，只写 `journal.sqlite`，**不会把当前 live run 的 AgentState 写入 Neo4j**；kg 页能查静态图谱和已有历史 run 的运行态追溯，但查不到 `wh-live-...` 这个 live run 的 AgentState。
- 要让 kg 页看到当前 live 的运行态，需要把 medium live 配成 Neo4j 运行态写入（`WAREHOUSE_NEO4J_WRITE_ENABLED=1` 等）并确保 runtime graph writer 可用；这是另一个运行配置，不是入口问题。
- 旧 legacy 4173 的 `dist/kg.html` 保留；medium 用 `dist/medium/kg.html`，两份页面功能相同，API 现在由 medium live 的 `/api/kg/warehouse/*` 提供。
