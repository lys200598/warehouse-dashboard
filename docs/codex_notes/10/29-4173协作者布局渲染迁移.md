# 4173 协作者布局渲染迁移

## 任务背景

用户要求将 4173 原控制台的旧 32×22、15 货架画面替换为协作者最新 balanced 仓库布局，同时保留 4173 的控制、WebSocket 和知识图谱入口。

## 关键结论

- 4173 现在通过新增的 `/api/layout` 读取 `warehouse100-expanded-balanced-v1` 布局，而不是在前端写死旧地图。
- 页面画布使用 100×90m、40 货架、1920 货位、16 个收发工位和 100 个泊位渲染。
- 4173 的数据源仍是旧 `SimulationCoordinator`；其 32×22 控制台坐标会映射到新布局工作区域，页面标题明确显示“控制台状态映射”。
- 映射仅解决视觉布局统一，不把旧控制台位置宣称为 V5 的真实路径，也不改变 14183 的 V5 历史回放定位。
- 旧后端前 15 个货架的占用/预约状态会叠加到新布局的同编号货架；其他扩展货架保持可视，避免页面只显示局部布局。
- 新布局的 IN/OUT 工位和 100 个泊位按 JSON 坐标绘制；离线演示模式也会从这些工位选择取货/出货位置。

## 执行过的操作

- 阅读 `dist/app.js`、`dist/index.html`、`backend/server.py` 和 `backend/simulation.py`，识别旧世界尺寸、货架生成和快照渲染链路。
- 在 `backend.server` 增加 `/api/layout`，只读返回已迁入的 balanced 布局 JSON。
- 在 `dist/app.js` 增加布局加载、40 货架/1920 货位生成、16 工位/100 泊位绘制及旧控制台坐标映射。
- 运行 Python 编译检查、布局 JSON 读取检查，以及图谱/仿真相关 12 项单元测试。
- 临时启动 14174 服务，Uvicorn 已正常完成启动；受控环境将本地 curl 请求重定向到其他端口，未能在此环境完成 HTTP/浏览器端到端请求。FastAPI TestClient 也因 `.venv` 缺少 `httpx2` 不可用。

## 修改内容

- 修改 `backend/server.py`：新增 `DEFAULT_DASHBOARD_LAYOUT` 与 `/api/layout`。
- 修改 `dist/app.js`：从后端加载布局，以协作者布局驱动画布，处理旧快照的货架/货位和机器人坐标映射。
- 未修改 `backend/simulation.py` 的旧控制台任务生成和坐标物理模型。

## 后续建议

- 启动 4173 后访问 `/api/layout`，再打开根页面确认 40 个货架和两侧收发工位可见。
- 后续将 4173 运行源替换为 V5 数据集/稳定提交帧时，移除 `mapLegacyPoint` 映射，直接使用 V5 米制坐标与真实货位状态。
- 若需要自动化页面验证，在项目虚拟环境中补齐与当前 Starlette 匹配的 HTTP 测试依赖，或用浏览器端到端测试验证画布。
