# 项目内容通读概览

## 任务背景

用户要求阅读当前仓库的全部内容，梳理项目定位、模块结构、运行入口、数据流和当前开发状态。本次为只读梳理，不修改任何代码或数据。

## 关键结论

- 项目是「100 机器人仓库仿真 + 时序知识图谱实验平台」，核心闭环为：CSV 数据集 → 静态图谱 → V5 仿真 → 运行态图谱写入 → 回放/查询。
- 平台有两条独立运行线：V5 批式仿真（`python -m backend.warehouse`，回放端口 14183）和 4173 实时控制台（`python -m backend.server`，FastAPI + Ray Actor）；两者共用 Neo4j，但必须是不同 `RUN_ID`。
- 后端约 2.06 万行 Python，按版本分层：`scheduling_v2 → v3 → v4 → v5`，V5 为选定策略（`port-guard` + `original-sipp`），继承 V4 运动引擎，只在 `_select_assignment` 留策略接缝。
- 知识侧由 `knowledge_runtime`（历史提供者/授权/接力）、`wide`（参数化仓库/数据校验/多日生成）、`real_scale`（运行态写入与向量）、`query_v2`/`query_catalog`（时序查询）组成；历史只在接力规划和交接前复核两个边界读取。
- 数据契约固定为 `layout.json` + `tasks.csv`（7 字段）+ `initial_inventory.csv` + `manifest.json`；基线布局 90×76m/36 架/1728 货位/100 泊位，协作者扩展布局 100×90m/40 架/1920 货位，两者并存。
- 图谱分静态（Warehouse/Zone/Rack/Location/Dataset/Goods/WarehouseTask）与运行态（Run/Robot/AgentState/Execution/RuntimeEvent）；本地 `journal.sqlite` 记录提交，`seq/commit_seq` 为查询水位。
- 前端是 `dist/` 下的原生 JS 静态页，无构建步骤：`index.html`（4173 控制台）、`kg.html`（图谱工作台）、`wide.html`（V5 回放）、`layout-preview.html`（布局预览）。
- 当前分支 `dev_261028-layout-migration` 正在迁移协作者布局能力（`balanced` 布局、自由端口 `port_relief`/`free_ports`、能力模型 `capabilities`、边界契约 `boundary_contract`），全部改动尚未提交。
- 测试共 68 个 Python 测试文件 + 4 个 Node `.mjs` 测试；文档记录上一轮完整回归为 569 项、562 通过、7 项可选集成跳过。
- `./run_in_lade.sh` 默认的 `../warehouse-deploy/.venv` 不存在，当前需用 `LADE_ENV_DIR="$PWD/.venv"` 指定仓库自带环境才能执行 Python。
