# 4173 并发日志序列修复

## 任务背景

4173 重启后点击播放，`/api/control` 抛出：

```text
backend.knowledge.KnowledgeError: non-contiguous journal sequence
```

本次定位并恢复，同时加固启动脚本，避免再次出现重复进程写同一 run。

## 关键结论

- 根因不是日志损坏，而是**两个 4173 进程同时写同一个 run/journal**：
  - 一个进程来自用户终端（pid 1832306），内存里的 `knowledge_seq` 停在 13525；
  - 启动脚本又拉起了一个重复进程（pid 1838746），把 journal head 推进到 13563；
  - 用户进程点击播放时尝试写 13526，而 journal head 已是 13563，于是报 `non-contiguous journal sequence`。
- 日志本身是连续的：`commits` 表中 `warehouse-3fafa0f3f4cb` 的 seq 为 1..13563，`heads.seq=13563`；`checkpoint` 文件里的 `knowledge_seq=13525` 只是旧快照。
- 启动脚本的端口检测在高负载/竞争时出现过假阴性，导致它在 4173 已被另一个进程占用时仍尝试启动，形成重复进程。
- 恢复方式：停止两个进程，保留一个；用 `--resume --allow-code-change` 从 journal head 重新恢复。恢复后 pause/resume 成功写入 seq 13601/13602，`/api/health` 显示 `status=ok`、`lastError=null`。
- 4173 的回放录制同时正常：`data/local-runs/console-warehouse-3fafa0f3f4cb/frames.sqlite` 持续增长，14185 把它标记为 `current: true`。

## 执行过的操作

- 读取 `backend/knowledge.py` 的 `JournalKnowledgeStore.append`、`latest_checkpoint`、`recovery_payload`。
- 查询 journal `heads` 与 `commits` 的 per-run seq 范围，确认 1..13563 连续。
- 对比 checkpoint 文件的 `knowledge_seq=13525` 与 journal head 13563。
- 检查 4173/14185 端口、进程、`/api/health` 和 `/api/control`。
- 强制停止卡住的重复进程，保留单一 4173 进程。
- 通过 `ops/start_runtime.sh --restart` 从 checkpoint/journal 恢复；验证 pause/resume、健康接口、回放帧。

## 修改内容

- `ops/start_runtime.sh`：
  - 增加 `flock`，防止两个启动脚本并发；
  - 端口检测增加重试，降低高负载下的假阴性；
  - 新增 `port_owned_by`，启动后校验端口确实由本次 PID 持有；
  - 若端口已被另一个实例占用，停止本次脚本拉起的重复进程，保留现有实例；
  - 停止 4173 时按 SIGINT → SIGTERM → SIGKILL 升级，避免卡死时无限等待；
  - 端口空闲时 `--restart` 不再误报“PID 不可见”；
  - 更新 `.runtime/pids/replay.pid` 为实际进程 1613017。
- 没有修改 journal 数据；没有删除历史 commits。

## 后续建议

1. 不要对同一个 checkpoint/run 同时启动两个 4173；需要并行实验时使用不同 `--checkpoint-path`、run 和 journal。
2. 启动统一使用 `bash ops/start_runtime.sh --restart`；不要在启动脚本运行期间再手动启动第二个 4173。
3. 若再次出现 `non-contiguous journal sequence`，先确认是否有重复进程，再重启单一进程从 journal head 恢复，不要直接清理 journal。
4. 5GB 的 `data/knowledge/warehouse.sqlite` 做完整 `PRAGMA integrity_check` 很慢；日常检查用 `heads`/`commits` 的 seq 连续性即可。
5. 后续可给 `JournalKnowledgeStore` 增加单实例文件锁，从源头阻止同一 run 的双写。
