# kg 页面任务追溯为空排查

日期：2026-10-30
分支：`integration/lys-wz-261030`

### 任务背景

4173 运行中，kg.html 点击“任务全链路”时提示：

> 暂无任务运行事件；启动带图谱写入的后端并运行仿真后可形成完整任务链路。

需要判断是仿真没有产生事件，还是图谱查询/写入有问题。

### 关键结论

- 任务事件其实已经写入 Neo4j；问题在查询过滤条件。
- Per-actor graph writer 的 `Execution.dataset_id` 是 `None`，因为启动时没有设置 `WAREHOUSE_NEO4J_DATASET_ID`。
- `task_execution_trace` 按 canonical medium Dataset id 过滤 `Execution`，因此查不到 `dataset_id=None` 的执行记录，连带 `RuntimeEvent` 也查不到。
- 前端 `latestRunId` 读取了 `health.runId`，但 `/api/health` 实际字段是 `runtime.runId`，导致任务追溯没有带当前 runId。
- 修复后按 `task_id + run_id` 查询，不再依赖 Execution 的 dataset_id；同时启动时把 canonical `graph_dataset_id` 传给 Ray actor graph writer。

### 执行过的操作

- 检查 4173 `/api/health`、`/api/snapshot`；
- 检查 Neo4j 中当前 run 的 `Execution`、`RuntimeEvent`、`ABOUT_EXECUTION` 关系；
- 对比 `task_execution_trace` API 返回与 robot trace；
- 修改图谱查询、API、kg.html；
- 重启 4173 验证 API。

### 修改内容

- `backend/warehouse_graph_query.py`
  - `task_execution_trace(task_id, dataset_id, run_id)` 支持 run_id；
  - 有 run_id 时按当前 run 查询，兼容 `Execution.dataset_id=None`。
- `ops/warehouse_live.py`
  - `/api/kg/warehouse/tasks/{task_id}/trace` 接收 `run_id` 查询参数。
- `ops/warehouse_live_runtime.py`
  - 创建 run 时设置 `WAREHOUSE_NEO4J_DATASET_ID` 为 canonical `graph_dataset_id`，供 Ray actor graph writer 使用。
- `dist/kg.html`
  - `latestRunId` 优先读取 `health.runtime.runId`；
  - 任务追溯请求附带 `run_id`。
