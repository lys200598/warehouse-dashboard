# 4173 运行态图谱一致性排查

## 任务背景

用户说明当前程序已经启动。本次对运行中的 4173 控制台、项目专用 Neo4j（47687）及其图谱查询接口做只读检查，判断「已经跑起来」之后下一步真正要解决的问题。

## 关键结论

- 4173 运行正常：`/api/health` 返回 `status=ok`、`backend=ray`、`taskSource=csv-dataset`、`runtimeGraph.writeMode=robot-actors`、`graphWriterErrors=0`，`runId=warehouse-f94d9be6882f`，100 个 worker，当前 tick 约 3500。
- 本机 `http_proxy/https_proxy=127.0.0.1:31090`，直接 `curl 127.0.0.1:4173` 会被代理转发并返回 502；必须加 `--noproxy '*'` 才能读到真实响应。这不是服务故障。
- **问题 1：`Run.robot_count` 被写成 1**。robot-actors 模式下每个 Ray Actor 用自己的单机器人快照执行 `MERGE (run:Run {id}) SET run += $run`，`robot_count=len(snapshot["robots"])=1`，后写覆盖前写。实际该 run 有 100 个 `Robot` 节点。
- **问题 2：`/api/kg/warehouse/tasks` 返回重复任务**。`task_list` 的 `OPTIONAL MATCH (e:Execution {task_id:t.task_id, dataset_id:d.id})` 会把同一任务在多个 run 中的 Execution 全部展开；T-000001 在图中有 16 条 Execution，接口 `limit=3` 返回了 3 条重复的 T-000001。
- **问题 3：`runtime-trace` 的 state 中 `robot_id` 全为 null**。`AgentState` 写入的是 `robot_node_id`（如 `run:robot:1`），没有 `robot_id` 属性；而 `runtime_state_trace`/`replay_states` 返回 `s { .robot_id,... }`，因此该字段为空。`Robot` 节点本身有 `robot_id`，需要 join 或解析 `robot_node_id`。
- **问题 4：AgentState 规模与 schema 混杂**。项目 Neo4j 当前约 10,091,532 个 `AgentState`，其中 8,670,845 个有 `run_id`、1,425,200 个没有；22 个 `Run` 累积在同一库，旧运行数据未清理。查询会随数据量增长变慢，且旧节点不满足当前查询契约。
- 当前 run 自身数据完整：约 93,029 个 AgentState、1,291 个 RuntimeEvent、215 个 Execution、100 个 Robot，`IN_RUN` 关系齐全，说明写入链路本身是通的。
- 另外：14186 是 `wz` 用户的 V5 live console（另一个部署目录），14183 是 `wz` 用户的 V5 回放进程，二者都不是当前仓库进程；当前仓库实际运行的是 4173。不要把它们当作同一 runId 的验证对象。
