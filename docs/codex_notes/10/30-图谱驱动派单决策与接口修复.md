# 任务背景

用户确认采用“图谱驱动派单”：主进程应从 Neo4j 的完整运行态读取调度输入。协作者反馈还指出全局记录服务因 `Request` 延迟注解与函数内导入组合，可能导致所有 POST/DELETE 请求返回 HTTP 422。

## 关键结论

- 当前全局记录服务的 `Request` 注解问题已最小修复：`Request` 改为模块级导入，FastAPI 可正确识别请求对象。
- 当前 `GET /steps/latest?states=true` 的精简状态和 4 tick 采样仅适合恢复/查看，不能直接作为图谱驱动派单输入。
- 图谱驱动派单的完整帧必须满足：100 个 Actor 每 tick 写入完整调度状态，成功后才回执；主进程收齐回执后推进 `Step`；随后只读该完整 Step。
- 图谱只提供状态输入；派单算法、库存与交通预约的决策权仍在主进程。
- 协作者的有状态 Actor 与主进程回执汇总是启用该模式的关键未完成部分。
