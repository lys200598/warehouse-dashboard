## 任务背景

14185 的多运行回放页此前只在下拉框中显示 Run ID/目录衍生名称。用户无法从文件名判断该记录的数据集、任务量，以及它是否仍在运行或写入。

## 关键结论

- 回放服务本来已经能通过 `latest.json`、`results.json` 和帧文件修改时间判断运行状态。
- 实时运行目录的 `live-manifest.json` 含有 `dataset_id`，可作为人能理解的主要选择依据。
- 下拉框改为展示运行状态、数据集、任务概况和已录制仿真时间，不再以目录名作为主要信息。
- 选中运行后会显示状态说明卡，明确区分“正在运行”“仍在写入”“已完成”“运行失败”和“已归档”。
- 14185 仍是只读回放服务；本次不改变数据格式、仿真流程或图谱写入。

## 执行过的操作

- 阅读 `backend/replay_service.py` 的运行目录发现和元数据接口。
- 阅读 `dist/wide.html`、`dist/wide.js` 的运行选择与回放初始化逻辑。
- 检查现有 `live-manifest.json`，确认实时运行已保存 `dataset_id`。
- 未启动服务、未运行仿真。

## 修改内容

- `backend/replay_service.py`：运行目录目录清单补充数据集 ID、任务总数、完成数和已释放任务数；优先复用已有 manifest、检查点和结果文件。
- `dist/wide.html`：增加选中运行的摘要卡，并调整运行选择控件和缓存版本。
- `dist/wide.js`：把运行标签改为语义化信息，添加状态/任务描述；刷新按钮会同时重新读取运行目录清单且保持当前选择。

## 后续建议

- 重启 14185 服务后刷新页面，确认新旧运行都能显示相应的状态和数据集。
- 若后续有业务名称，可在运行 manifest 中新增 `run_label`，再优先显示该名称，而不是人工依赖 Run ID。
