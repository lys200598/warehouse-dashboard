# 测试知识图谱接入

### 任务背景

为现有仓储机器人仿真尝试接入可展示的测试知识图谱，不依赖 Neo4j 或外部服务。目标是验证“仿真状态 → 局部知识图 → 前端展示”的接口形态，为后续百万级持久化图谱保留替换边界。

### 关键结论

- 新增内存测试图谱，直接从协调器的权威仿真快照生成 `Run`、`Robot`、`Task`、`Rack`、`Zone`、`Event` 与最近 `RobotState` 的局部图。
- 新增 `GET /api/kg/summary` 与 `GET /api/kg/robots/{robot_id}/subgraph`；前者返回节点/关系估算与 Step，后者只返回选中机器人的有限邻域。
- 测试知识图谱仅保留后端摘要与局部子图接口；右侧设备详情的测试知识图谱面板及其前端请求逻辑已按后续“尽量不改前端”的要求删除。
- 图谱历史默认只保留最近 30 个 Step，且浏览器仅渲染最多 5 个相关节点，避免把全量图推向浏览器。
- 这是内存测试数据，不是 Neo4j 持久化实现，不具备百万级数据容量、跨重启历史、查询优化或 100 并发 SLA 证明能力。

### 执行过的操作

- 新增 `backend/knowledge.py`，实现 `InMemoryKnowledgeStore`。
- 在 `backend/server.py` 中同步当前仿真快照，新增两个只读 KG 接口。
- 曾修改 `dist/index.html`、`dist/styles.css` 和 `dist/app.js` 进行图谱展示试验；该展示试验现已移除，前端恢复为既有仓储看板（页脚 CSV 数据源标识除外）。
- 新增 `tests/test_knowledge.py`，覆盖快照派生、历史上限及 FastAPI 路由的无网络调用。
- 执行 `./.venv/bin/python -m unittest discover -s tests -v`：11 项通过；执行 Python 编译与 `git diff --check` 通过。

### 修改内容

- `backend/knowledge.py`：内存测试图谱与局部子图装配。
- `backend/server.py`：维护测试图谱快照，并暴露摘要/子图 API。
- `dist/*`：知识图谱测试面板已删除；不再对其进行前端请求或渲染。
- `tests/test_knowledge.py`：图谱与 API 契约测试。

### 后续建议

- 将 `InMemoryKnowledgeStore` 抽象为正式接口，并增加 `Neo4jKnowledgeStore`；保留现有 API 返回格式。
- 在协调器每个 tick 完成后批量异步写入持久化图谱，增加 `Run` 隔离和 schema/index migration。
- 用仓储数据生成器构建独立百万级图谱，随后才开展 100 智能体并发查询验证。
- 沙箱禁止本地 socket，未能以浏览器/HTTP 回环方式验收页面；如后续明确需要图谱界面，可基于保留的 `/api/kg/summary` 与 `/api/kg/robots/{robot_id}/subgraph` 接口另行设计。
