- 用户最终目标是参考 KG_Embodied 与 LaDe 完成「仓储机器人 + 知识图谱」闭环，而不是只做动画页面；当前优先级是 `数据集 → 静态图谱 → 4173 实时执行/写图 → 图谱查询` 的可见闭环。

- 最重要的边界：14183 是 V5 历史帧回放；4173 是实时服务，任务源已可接 CSV，但运动/交通内核仍是 `SimulationCoordinator`，轨迹与 V5 不一致；4173 前端布局用了兼容映射层。
- 已完成：数据生成器与百万运行态样本、静态图谱导入与查询、扩展布局渲染、4173 CSV 接入、Ray Actor 自主写运行态图谱（`robot-actors` 模式）。
- 验证状态：`test_live_dataset_source`、`test_robot_actor_graph`、`test_simulation`、`test_warehouse_runtime_graph` 共 15 项通过；真实 Ray + Neo4j 联调未做，不能把单测当作压测结论。
- 最大未完成项：统一 4173 与 V5 运行内核。推荐新增 `backend.server` 的 V5 实时适配模式，在 V5 稳定提交点同时更新 WebSocket 快照、写 `frames.sqlite`、写 Neo4j，最终共用同一 `runId`。
- 其他后续：`kg.html` 自动带入当前 `runId`；百万 AgentState 的 100 并发 <500ms 压测尚未在目标硬件验收；布局/机器人/充电策略以协作者分支为准。
- 修改约束：保留 `backend/runtime.py`、`server.py`、`simulation.py`、`domain.py` 当前接口；不用协作者旧版整体覆盖；禁止 `git reset --hard`、`git checkout --`、全局 `ray stop --force`；不共用 checkpoint；改图谱模型需同步静态导入、运行态 writer、查询 API、`kg.html` 与合同文档。
