## 任务背景

将 4173 仓库运行页的初始状态调整为自动开始、60 倍速，避免页面在首帧或新 Run 初始化时显示为暂停、1 倍速。

## 关键结论

- 4173 的 `WarehouseLiveRuntime` 新建或恢复未完成 Run 时默认 `running=true`、`speed=60.0`。
- 旧 `SimulationCoordinator` 入口也统一为运行、60 倍速，且控制接口允许 20/60 倍速度，与页面已有按钮一致。
- 页面本地首帧状态同步改为运行、60 倍，并将 60× 标为默认选中项。
- 显式使用 `--start-paused` 时仍会按该参数暂停，保留人工受控启动能力。

## 执行过的操作

- 阅读 `ops/warehouse_live_runtime.py`、`backend/simulation.py` 的新 Run 初始化及速度控制校验。
- 阅读 `dist/app.js` 和 `dist/index.html` 的 4173 页面初始状态与速度按钮。
- 执行 `git diff --check` 静态检查。

## 修改内容

- `ops/warehouse_live_runtime.py`：将 4173 真实运行器的新建/未完成恢复 Run 调整为启动即运行，默认速度 60 倍。
- `backend/simulation.py`：将旧入口的权威速度默认值设为 60 倍，并将 20/60 纳入可选速度。
- `dist/app.js`：将后端快照到达前的页面默认状态设为运行、60 倍。
- `dist/index.html`：将默认高亮速度从 1× 改为 60×。

## 后续建议

- 重启 4173 服务后，新创建的 Run 会使用这套默认值；已有恢复检查点仍会恢复其保存的运行状态和速度。
- 若某个部署脚本显式添加了 `--start-paused`，应移除该参数才能自动开始。
