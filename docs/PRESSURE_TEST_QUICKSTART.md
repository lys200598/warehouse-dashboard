# 压测：只运行一条命令

**更直观的用法：执行 `python pressure_test.py --gui` 打开[独立网页控制台](PRESSURE_GUI_GUIDE.md)，选参数、启动/停止、查看图表和历史。** 下文保留终端菜单用法。

适用于客户端有Python 3.10以上、已有Neo4j模式实时服务的情况。无需填写run_id、seq、工作负载文件名或输出目录，也无需单独运行分析命令。

## 1. 打开向导

在服务器项目根目录执行：

```bash
bash pressure_test.sh
```

已有Python环境也可以直接运行 `python pressure_test.py`；Windows同样可用这条Python命令。工具使用标准库，不需要在压测客户端安装Neo4j或GPU依赖。服务端仍需有正常运行的图谱服务。

Bash入口会优先使用显式LADE_ENV_DIR，再查项目.venv、已有部署环境，最后查系统Python；只选择现有环境，不自动安装包或改全局配置。

出现以下菜单：

```text
服务地址 [回车使用http://127.0.0.1:14192]：
1. 连通性小检查：1客户端×3次（推荐先选）
2. 日常错峰：100客户端，每人5秒最多一次，测10秒
3. 轻查询突发：100客户端，每人最多2次
4. 全局重查询突发：100客户端，每人最多2次
选择 [回车选1]：
```

第一次一路回车即可。14192是当前Pro6000部署示例；若使用其他服务，填其实际地址，端口不对就不能连接。服务器上执行时填服务器自己的地址；本机执行时需要能访问该地址，例如先建立SSH端口映射。

方案2—4会额外要求输入 `yes`，确认使用自己的测试服务。默认不会自动发100客户端压力，不会启动、暂停、切换或重置仿真。

## 2. 等它显示结果

向导会自动完成：

1. 检查服务、查询目录，找到当前run_id和已写入Neo4j的seq。
2. 固定这个知识提交点，先做1次额外查询和结构校验。失败就停止，不盲发100次。
3. 使用原load_harness执行所选方案，保存全部请求、失败和完整响应。
4. 调用原分析器，生成中文结果和原始统计。

结果自动保存到 `data/local-load/easy-时间-随机编号/`，屏幕会显示完整位置。

|看什么|打开哪里|
|---|---|
|中文结论、平均/P99/最大值、失败数量|`report.md`|
|供程序读取的摘要|`summary.json`|
|原分析器完整结果|`analysis.json`|
|每客户端完整请求、响应和计时|`client/`|
|那条额外连通性检查|`preflight.json`|
|工具异常原始信息|`run.log`、`analyze.log`|

输出目录自动换新，指定已有目录会拒绝覆盖。慢请求和错误不自动重试、过滤或删除。Ctrl+C沿用原压测器的停止与子进程清理流程，已有结果保留为未完成。

## 3. 这次“通过”具体指什么

通过指**本次样本的完整HTTP＋JSON延迟及catalog结构检查**满足要求。不是项目全部验收通过。

- 当前批次是启动检查时固定的历史点，期间服务仍可继续运行；工具不保证每条请求都读取当时最新批次。
- 100个客户端不一定产生100条同时在途请求。默认没有完整服务端观测日志，所以真实API峰显示“未取得完整有效证据”。
- 没有独立journal/oracle验真，也没有自动证明百万规模、100台实际工作或持续写入。摘要明确保留这些资格为false。
- 先查询过一次，不能把结果叫作全冷；也没证明所有查询worker都已预热。
- 本入口只测公开catalog查询，不测Agent私有读写、ANN或百万A/B。它们的正式验证继续用[完整手册](LOAD_TEST_COOKBOOK.md)。

退出码：0为本轮样本条件满足；2为延迟、错误或结构检查条件未满足；1为准备/工具失败；130为用户中断。屏幕中文结论与原始报告一起看。

## 4. 不想每次选择菜单

以下为直接运行方式；URL只需改成自己的服务：

```bash
# 小检查：不用确认，不施加100客户端负载
bash pressure_test.sh --url http://127.0.0.1:14192 --profile quick

# 自己的测试服务：明确同意100客户端错峰查询
bash pressure_test.sh --url http://127.0.0.1:14192 --profile normal --yes
```

`--profile burst --yes`是轻突发，`--profile heavy --yes`是全局重突发。每个方案的请求数/持续时间属于实验负载，不能把改变负载后的结果混作同一次验收。

## 5. 改API以后需要动哪里

日常用户只使用向导；接口整合者维护一次配置即可：

- 端口变了：输入新地址，或修改 `config/pressure-test.json` 的base_url。
- health/catalog路径或health字段层级变了：修改该配置中的路径与字段路径列表。
- POST查询路径变了：修改配置后，还需按原发起器安全规则更新只读路径白名单，或保留兼容旧路由。向导不绕过它。
- 请求/响应字段、hash、认证或图谱业务语义变了：需要同步修改适配与校验。当前向导依赖标准catalog结构，不自动猜新协议，也不负责登录、获取私有Agent凭证。
- 生产Cypher、图谱标签或journal格式改变后的完整来源验真，继续按[兼容矩阵](LOAD_TEST_COOKBOOK.md#8-改代码以后哪些还能用)处理。

这个入口把原工具串起来，保留原始测量、失败分母和校验规则；它没有另写一套更宽松的成绩计算方法。
