## 1. 已整理进分支的功能

- `python -m backend.warehouse`统一校验、生成、运行、查询、回放和检索评估。
- `query_catalog`提供11个仓库知识包，逐项说明KG_Embodied 56模板的对应关系。
- `required`在低电接力规划和实际交接前读取共享历史并授权；`rules`用于同输入对照。
- 固定数据集支持任意合法时长；任务数量、采样周期和运行资源使用独立预算。
- 原32D ANN工程基线继续保留，新增17D有界精确业务检索与独立质量评估。
- 新ops提供实际100机器人回放、完整响应验真、控制链审计、读写重叠及逐请求规模审计。

当前知识实验使用中央协调器维护100台机器人。机器人实体、同时业务活动数量、API在途数量和Ray进程数分别记录。LLM保持不启用。

## 2. 100台同时业务活动的实际证据

当前冻结源完成了1728条高峰任务，迟到0，结束于4179模拟秒，平均流转380.68秒。100台均执行过任务。

为独立验证“同时工作”，`ops/replay_hundred_frame.py`用同一输入、物理配置和源码确定性重放：0至800秒的81个原始采样帧、8100个机器人样本所有字段精确匹配。804秒有35台去取货、52台运输、8台取货、5台放货，共100台业务活动。804秒是实际帧锚定的重放结果，原回放库仍保留其10秒采样。

全部804步另用相对运动线段距离检查3,979,800组机器人对，满足1.1m安全间距。源帧库前后SHA一致。见[机器证明](evidence/platform-v1/hundred-replay-proof.json)。

高峰回放地址为服务器14184端口；本机SSH转发已建立时访问`http://127.0.0.1:14184/`。原14183小样例及旧服务保留。

## 4. 查询正确性、并发与延迟分开看

60,240次轻量请求及18次功能请求的完整JSON均通过独立来源核对。验真在请求结束后执行，读取原journal与独立索引，不计入服务耗时。

|轻量轮次|请求数|逻辑client|真实API峰值|平均ms|最大ms|
|---|---:|---:|---:|---:|---:|
|1|2000|100|100|9.12|117.17|
|2|2000|100|100|10.72|146.57|
|3|2600|100|100|11.06|194.61|
|4，50ms客户端思考间隔|53,640|100|61|4.23|149.07|

四轮均0错误、0条超过500ms，同一run图水位均在实际请求窗内推进。第4轮响应很快，客户端思考时没有API在途，100个逻辑client的实际峰值只有61。因此，要求每轮实际峰值均达到100的[组合审计](evidence/platform-v1/week-300s-joint-audit.json)明确失败这一项；原样保留该结果。

全体轻量请求混合均值为4.90ms、P99为23.45ms、最大194.61ms。各轮的到达模式不同，比较性能时应优先看单轮。18次功能查询0错误，其中4次区域/全局完整任务统计超过500ms，最大1383.46ms。这些统计适合中央共享读取；高频单机器人读取继续使用轻量包。

低电规划发生在第4轮时间跨度中，但该轮存在无请求空档，且交接在该轮后完成。当前严格“整个控制bracket被真实API在途区间覆盖”的证明为false。来源与动作正确性已通过，实际持续压力覆盖在新回归中补验。

最初过大的连接池还产生了31次`NoThreadsAvailable`，失败样本保存。后续采用8进程×3条业务Bolt连接，另留写者/观察器预算；等待连接的时间仍计入API耗时。数据库线程上限32与100个客户端分别计量。
