# 仓库向量检索：用途、特征、算法和验收

这份说明面向首次接触项目的同学。仓库任务CSV负责定义货物何时进出、来源和目标；仿真运行产生机器人状态、任务变化及协作事件。向量检索在这些历史记录中寻找相似状态，再由任务、货物和事件关系解释结果。

向量把位置、电量和工作阶段转换为数字特征，余弦相似度用于比较这些特征。ANN是Approximate Nearest Neighbor，意为近似近邻检索：通过索引更快寻找相似候选，允许漏掉少量真正最近的记录。精确TopK会完整比较声明的候选域；当前小窗口采用这条精确路线，原HNSW索引用于保留的ANN对照。

## 1. 两条检索路线

|路线|作用|当前实现|
|---|---|---|
|原32维工程向量|维持既有百万图性能、来源与索引回归|Neo4j向量索引，ANN100→1000→必要时精确补查；完整图/时序上下文保持原契约|
|新17维业务结构向量|按明确物理特征寻找历史相似状态|先限定run和历史窗口，再对完整且有预算的候选域做精确余弦TopK；无需新增索引或修改旧图|

普通货权查询按任务和货物编号读取，继续使用轻量接口。相似检索用于“过去有没有相近状态”的建议，当前不直接授权派单或货权转移。授权继续经过已提交来源、当前货权、能量和交通门禁。

数据生成后，是否调用向量检索由查询问题决定。比如“G001现在由谁拿着”使用货物ID和时序关系；“以前有哪些低电载货状态与机器人37相近”使用相似检索，再读取命中状态的任务和协作事件。任务CSV提供共同的实验输入，运行产生的真实状态构成检索对象。当前`similar_history`默认选择17D `business-exact`；`full-ann`需要显式选择。

## 2. 原32维向量表达了什么

`real_scale.real_vector`沿用工程压力表示：位置、电量、载货、机器人编号、阶段序号、提交时刻的正余弦，加24维由提交编号与机器人编号派生的小幅身份特征。整体做L2归一化。

身份与周期时间帮助区分大量相似待命快照，适合观察索引在真实数据上的工作情况。它们也会影响近邻顺序，因此“索引找到了向量近邻”不能自动推出“找到了最相关的协作经验”。原32维向量和既有测试保留原身份，后续质量测试额外排除查询机器人和最近时间片，避免只凭自检命中得出高召回结论。

## 3. 新17维业务特征

版本为`warehouse-business-state-v1`：

1. 一个固定偏置，保证合法状态不会得到零向量；
2. x与1-x、y与1-y，按本run地图宽深归一化；
3. SOC与1-SOC，SOC以百分数/100归一化；
4. 载货与空载两个互补分量；
5. 8个互斥阶段族的one-hot：待命、运输、取放、充电、回充、协作、故障/恢复和未知。

最后做L2归一化，以原始余弦相似度排序。机器人ID、任务ID、货物ID、时间和身份盐均不参与距离。阶段采用类别编码，避免把阶段序号大小误当成连续距离。

这是可解释的人工结构特征。不同业务可能需要不同权重、路线距离或任务类别；当前模型没有学习文本/图像语义，也没有预测协作成功率。两种特征空间的分数不能直接比较为同一种“置信度”。

## 4. 实际可调用的精确检索接口

```python
from backend.retrieval_eval.service import BusinessRetriever

result = BusinessRetriever(mirror, timeout=15).search(
    run="your-run", seq=1000, robot_id=37,
    k=5, window_steps=60, embargo_steps=20,
    max_candidates=10000, exclude_query_robot=True,
)
```

- 查询状态必须在已提交知识水位内，源payload摘要与实际请求匹配。
- 候选来自同一run的`[max(1, seq-window_steps), seq-embargo_steps]`，默认排除查询机器人的整条轨迹。
- `window_steps`与`embargo_steps`单位为**提交批次**；5秒周期采样下默认回看300模拟秒，排除最近100模拟秒。若改为300秒周期采样，相同参数约回看5模拟小时、排除最近100模拟分钟。扰动和关键边界会增加提交，因此严格时间窗应按任务需求另行定义，不能将批次差始终当作固定模拟时间差或现实墙钟差。
- 读取最多`max_candidates+1`条以检测超预算；超额明确抛出`CandidateBudgetExceeded`，不会悄悄将截断集合冒充精确全集。
- 在完整候选域内精确排序；不足K或零候选按实际数量返回，不补未来状态或当前自身。
- 返回源key、机器人/提交编号、物理特征、源payload摘要、分数、候选范围及候选数量，可回表任务和协作关系。
- 查询调用包含来源读取、实际Neo4j候选读取和精确排序；`stage_ms`区分三个阶段。该接口纯标准库加现有Neo4j驱动，不依赖NumPy。

默认窗口在完整100机器人采样源中最多产生41×99=4059个候选。缩小窗口或改变排除条件会改变业务问题，调用方需要显式记录；性能比较使用同一候选域。

## 5. 怎样比较算法质量

评估入口：

```bash
./run_in_lade.sh python -m backend.retrieval_eval \
  --oracle-index /absolute/path/to/verified-oracle.sqlite \
  --output /absolute/path/to/new-evaluation \
  --max-states 1000000 --queries 12 --neo4j
```

矩阵评估使用可选NumPy，安装在自己的实验环境即可；普通业务精确接口无需该依赖。`--neo4j`通过现有环境变量配置只读连接，禁止创建索引、写图或改原始日志。输出目录必须是新目录。

评估包含两层真值：

1. **数学检索正确性**：用来源payload重新构造向量，对完整合法前缀做NumPy float64精确余弦检索；每case另取最多10,000个合法候选，用独立`math.fsum`标量余弦交叉校验。ANN召回按同一旧32维特征、同一合法候选域对比精确TopK。
2. **业务相关性**：独立规则定义为相同载货状态、相同阶段族、电量差≤10个百分点、位置相距≤15m。该标签不使用余弦分数，同时报告候选域中有多少相关状态、可达到的Precision@K上界。它检验一个明确结构用途，不等于配送成功或创新性收益。

查询case使用真实来源状态：低电载货记录按`(机器人, seq//200)`去重复，其余点覆盖完整来源前缀；查询集不按最终效果挑选。候选排除整条查询机器人轨迹及20提交时间隔离，严禁未来数据和跨run结果。零相关历史的早期case仍保留在总分母中。

## 6. 选型与性能原则

Neo4j现有向量索引由Apache Lucene支撑，配置包含HNSW的连接和构建搜索参数，适合复用现成索引而不自研图索引。[Neo4j官方向量索引文档](https://neo4j.com/docs/cypher-manual/5/indexes/semantic-indexes/vector-indexes/)

小而明确的候选域可以先使用精确检索。Faiss官方选型指南将Flat列为精确基线，并指出搜索次数较少时应考虑索引构建成本；本项目当前实现使用标准库/NumPy精确计算，未调用Faiss。[Faiss官方选型指南](https://github.com/facebookresearch/faiss/wiki/Guidelines-to-choose-an-index)

本轮保留旧HNSW工程基线，新增有界17维精确建议接口。若未来需要对大量全历史业务向量持续检索，可另建独立特征版本和索引，再比较HNSW与Flat。更换表示、候选域和索引都要明确版本，避免拿不同语义的查询直接比较毫秒值。

依赖与引用边界：NumPy按其官方许可证使用；Faiss只作为选型参考，其MIT许可证允许开源复用但本轮没有引入代码。Neo4j服务与驱动继续按各自官方许可使用，Git中不包含Neo4j二进制、独立复制的实验驱动或数据库凭据。[NumPy许可证](https://numpy.org/doc/stable/license.html)、[Faiss许可证](https://github.com/facebookresearch/faiss/blob/main/LICENSE)、[Neo4j Python驱动](https://github.com/neo4j/neo4j-python-driver)

实测摘要及完整分母见[选型证据报告](evidence/platform-v1/vector-selection-report.md)和[机器摘要](evidence/platform-v1/vector-selection-summary.json)。选择方案需要同时考虑业务相关性、数学召回、候选覆盖、单次/并发延迟、写入维护和存储成本。

## 7. 本轮实测摘要

在百万实际状态中分层选择12个查询，最后一个查询涵盖988,020个合法历史候选。17D与32D的业务Precision@5分别为0.8167、0.4333；按声明的独立结构标签，该组数据可达到的上界为0.8167。两次低电查询没有相关历史，最早查询只有4条相关历史，全部保留。样本数较小，该结果用于选型，不是全场景相关性保证。

上述0.8167使用**完整允许历史前缀**评估表示质量，包含最近20提交隔离和排除查询机器人；正式业务接口默认使用**60提交回看窗口**控制成本。两者分别回答“这种特征是否合适”与“有限历史域内接口是否正确、耗时多少”，有限窗口的业务覆盖应随最终查询集另行评估。

同32D数学真值下，ANN100/1000的Recall@5均值为0.7833/0.85，说明排除自身并严格过滤历史后需要继续关注候选覆盖。当前完整接口保留精确补查，新业务接口直接在明确的小域内精确排序。

新业务接口4次实际图/来源核对全部通过，候选各4059条，完整服务耗时约296、156、148、182ms。原始实现的1014ms首冷和其他负结果保留。内存矩阵速度、来源构造、数据库返回与并发性能分别记录，不从这些串行诊断推导100客户端达标。

环境分开记录：百万前缀矩阵与ANN质量诊断使用已有Anaconda Python3.13、NumPy及独立纯Python驱动；4次实际业务接口和下面的服务端原型使用现有CPython3.10环境及Rust驱动。各自的计时范围不同，不能合并成一组生产并发数字。

数据生成同学继续按七字段CSV、位置编号、初始库存及容量契约交付，无需在CSV加入向量或电量列。需要更多可复用协作历史时，通过独立运行配置增加重复的低电/故障/接力场景，保留真实状态、事件及结果供评价。

## 8. 下一阶段提速：服务端精确TopK原型

已增加独立只读工具`ops/probe_business_exact_server.py`。它把同一17D构造和精确排序下推到Cypher，先检测候选预算，再只返回TopK与候选数量，减少约4059行候选跨Bolt返回及Python逐行物化。工具保留run、截止水位、源摘要、完整候选域和排除条件；使用标准Cypher，无APOC、新索引或图写入。

|两轮各24次平均|230.153ms|146.898ms|
|两轮最大|309.628ms|1121.801ms|
